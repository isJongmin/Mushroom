# 화면 설계: 캐릭터 생성

버전: 2.0 (2026-10-14, 사이클 2 픽셀 스킨). 흐름, 닉네임 규칙, 상태, 오류 문구, 완료 흐름은 v1과 같다. 바뀐 것: 2장(레이아웃, 배경), 3장(미리보기: 4배 걷기 애니메이션), 5장(파츠 목록 확장과 행 스킨), 버튼 스킨.
참조: `docs/design/style-guide.md` (아바타 5장, 파츠 목록 5.5–5.10, UI 스킨 7장). 저장 값은 `characters.avatar` 형식 `{ "skin", "hair", "eyes", "top", "bottom" }`.

## 1. 목적과 진입 (v1과 같음)

- 계정당 캐릭터 1개. 캐릭터가 없는 계정만 이 화면에 들어온다.
- 진입 경로: 회원가입 성공, 캐릭터 없는 계정으로 로그인.
- 완료 후: 인게임 (`game.md`)으로 이동.
- 이 화면을 떠나는 방법: "로그아웃" 버튼 (로그인 화면으로). 캐릭터가 있는 계정이 이 화면에 들어오는 경우는 없다.

## 2. 레이아웃

### 2.1 공통

- 배경: 로그인 화면과 같은 마을 맵 배경 캔버스 (`login.md` 2.1). 로그인에서 넘어오면 배경을 다시 만들지 않는다.
- 카드: 픽셀 패널 (`.px-panel`, style-guide 7.2). 내용은 바깥 끝에서 24px 안쪽.
- 카드 맨 위 줄: 왼쪽 제목 "캐릭터 만들기" (`fs-lg` 20px 700 `--text`, `<h1>`), 오른쪽 "로그아웃" 작은 보조 버튼 (높이 32px, 글자 `fs-sm` 14px 700, 가로 패딩 8px, 터치 영역은 위아래 6px 투명 확장으로 44px 확보). 제목 줄 아래 16px.
- LOCAL MODE 줄 (local 모드만): 카드 맨 아래, 만들기 버튼 아래 16px (style-guide 7.9).

### 2.2 데스크톱 (720px 이상)

2열 구성. 카드 가로 720px (스킨 포함), 카드는 뷰포트 세로 가운데 (뷰포트보다 길면 위 32px부터).

| 열 | 가로 | 내용 (위 -> 아래) |
|---|---|---|
| 왼쪽 (미리보기) | 280px | 미리보기 상자 208 x 256 (가운데 정렬) -> 16px -> 닉네임 필드 + 상태 줄 -> 16px -> 만들기 버튼 (가로 280px) |
| 오른쪽 (파츠) | 나머지 (720 - 48 - 280 - 24 = 368px) | 파츠 행 5개 (피부, 머리, 눈, 상의, 하의) |

열 사이 간격 24px.

### 2.3 모바일 (720px 미만, 최소 360px)

세로 한 열. 카드 가로 = 뷰포트 - 32px (360 폭에서 328px, 내용 폭 280px). 카드 위 여백 16px.

순서 (위 -> 아래):
1. 제목 + 로그아웃
2. 미리보기 상자 208 x 256 (가운데)
3. 닉네임 필드 + 상태 줄
4. 파츠 행 5개 (각 행 높이 56px)
5. 만들기 버튼 (가로 100%, 높이 48px). `position: sticky; bottom: 8px;` 버튼 뒤 배경이 비치지 않게 버튼 아래 8px까지 `c1` 띠를 둔다 (`box-shadow: 0 8px 0 #FFF6E4`)
6. LOCAL MODE 줄

가로 스크롤 금지. 360px에서 파츠 행: 라벨 48 + ◀ 44 + 값 (가변, 최소 120) + ▶ 44 + 간격 8 x 2 = 280px 안에 들어간다. 값이 넘치면 말줄임 (`…`).

## 3. 미리보기

| 항목 | 값 (데스크톱, 모바일 공통) |
|---|---|
| 상자 | 바깥 208 x 256 CSS px = 테두리 `4px solid #5E3620` (w4) + 안쪽 여백 `4px` 바탕 `#8A5232` (w3) + 캔버스 192 x 240 |
| 캔버스 | 아트 48 x 60 px를 4배로 표시 (CSS 192 x 240, 백킹 x dpr, 스무딩 끔) |
| 하늘 | 아트 y 0–19 `k3`, 20–33 `k4`, 34–47 `k5` |
| 땅 | 아트 y 48–59에 `ground.png`의 x 0–47, 행 0–11을 그린다 (풀잎 y 48–51, 잔디 윗면 y 52) |
| 아바타 | 프레임 왼쪽 위 (8, 6) → 기준점 (24, 52). 4배 = 128 x 192 CSS px |
| 발 그림자 | y 52: x 18–29, y 53: x 19–28, `g3` (style-guide 4.5와 같은 규칙) |
| 애니메이션 | 걷기 `walk0 → walk3` 프레임당 120ms 반복, 오른쪽 방향. 제자리 걸음 (땅은 움직이지 않음) |
| 방향 버튼 | 상자 오른쪽 아래 안쪽 (캔버스 오른쪽 4px, 아래 4px)에 작은 보조 버튼 32 x 32, 글자 "↔" `fs-sm` 700. 누르면 좌우 반전 토글. `aria-label="미리보기 방향 바꾸기"`. 키보드 포커스 가능 |
| 동작 줄이기 | `prefers-reduced-motion: reduce`이면 `idle0` 정지 화면 |
| 로딩 | 파츠 PNG를 불러오는 동안 캔버스 바탕 `k4` + 가운데 로딩 점 (`login.md` 5.1) |
| 오류 | 어떤 파츠 PNG가 실패하면 그 레이어만 빼고 그린다 (콘솔 경고 1회). 화면 오류 문구 없음 (생성은 가능) |

- 아바타는 style-guide 5장 규격대로 레이어 순서(skin, bottom, top, eyes, hair)로 합성한다.
- 파츠를 바꾸면 다음 프레임부터 즉시 반영한다. 애니메이션 위상은 끊지 않는다 (걷기 프레임 번호 유지).
- 캔버스는 `aria-hidden="true"` (대체 설명은 파츠 행의 값 글자가 담당). 방향 버튼만 포커스 대상이다.

## 4. 닉네임 입력 (v1과 같음, 스킨만 변경)

### 4.1 필드

| 항목 | 값 |
|---|---|
| 라벨 | "닉네임" (`fs-sm` 14px 700) |
| 입력 | 높이 44px, `input-*` 스킨 (style-guide 7.4), `fs-md` 16px, `maxlength="12"`, `autocomplete="off"`, `spellcheck="false"` |
| 허용 문자 | 한글 완성형 (가-힣), 영문 대소문자, 숫자 |
| 검사 정규식 | `^[가-힣a-zA-Z0-9]{2,12}$` |
| 도움말 (기본 상태) | "2~12자, 한글, 영문, 숫자만 사용할 수 있습니다." (`fs-xs` 12px 700 `--text-muted`) |

규칙:
- 한글 자모(ㄱ, ㅏ 등 조합 중이거나 낱자)는 완성형이 아니므로 형식 오류로 처리한다.
- 공백, 특수문자, 이모지 금지. 입력 시 공백을 막지 않고 형식 오류로 알린다.
- 대문자와 소문자는 구분하지 않고 중복 판단한다 (서버 기준). 클라이언트 중복 판단은 서버 응답에 따른다.
- 입력 값 앞뒤 공백은 제거하고 검사한다.

### 4.2 상태 줄 (닉네임 필드 아래, 높이 20px 고정)

상태 줄의 높이는 항상 20px로 고정해 상태가 바뀌어도 화면이 흔들리지 않는다. 글자 `fs-xs` 12px 700.

| 상태 | 조건 | 글자 색 | 문구 | 아이콘 |
|---|---|---|---|---|
| 미확인 | 형식은 맞지만 아직 확인 안 함 | `--text-muted` | "중복 확인이 필요합니다." | 없음 |
| 형식 오류 | 정규식 불일치 | `--error` | "2~12자의 한글, 영문, 숫자만 사용할 수 있습니다." | 없음 |
| 확인 중 | 중복 확인 요청 중 | `--text-muted` | "확인 중..." | 로딩 점 (`login.md` 5.1, 점 크기 2px로 축소) |
| 사용 가능 | 서버 응답: 사용 가능 | `--success` | "사용할 수 있는 닉네임입니다." | 체크 "✓" |
| 중복 | 서버 응답: 이미 사용 중 | `--error` | "이미 사용 중인 닉네임입니다." | 없음 |
| 확인 실패 | 네트워크 또는 서버 오류 | `--error` | "닉네임 확인에 실패했습니다. 다시 시도하세요." | 없음 |

필드 스킨:
- 기본 `input-normal`, 포커스 `input-focus`.
- 형식 오류 또는 중복: `input-error`, `aria-invalid="true"`.
- 사용 가능: `input-normal` 그대로 (상태 줄의 ✓와 초록 문구로 표시).

### 4.3 중복 확인 시점 (v1과 같음)

- 값이 형식에 맞고 입력이 500ms 멈추면 자동 확인 (디바운스 500ms).
- 필드에서 포커스가 떠날 때 (blur), 형식이 맞고 아직 현재 값으로 확인하지 않았다면 즉시 확인.
- 값이 바뀌면 상태는 "미확인"으로 돌아간다. 이전 결과를 현재 값에 재사용하지 않는다.
- 만들기 버튼을 눌렀을 때 상태가 "사용 가능"이 아니면 확인부터 하고, 사용 가능이면 바로 생성 요청을 보낸다.
- 확인 응답은 참고용이다. 최종 중복 판단은 생성 요청 시 서버가 한다 (`409` 같은 중복 응답 -> "중복" 상태).

## 5. 파츠 선택 UI

### 5.1 행 구성

| 순서 | 파츠 | 라벨 | 옵션 수 | 기본값 |
|---|---|---|---|---|
| 1 | skin | 피부 | 3 | `skin-light` |
| 2 | hair | 머리 | 7 | `hair-round-black` |
| 3 | eyes | 눈 | 4 | `eyes-dot` |
| 4 | top | 상의 | 4 | `top-tee-red` |
| 5 | bottom | 하의 | 4 | `bottom-shorts-navy` |

### 5.2 옵션 표시 이름 (값 글자 = 매니페스트 label)

| 파츠 | 옵션 순서 (왼쪽 -> 오른쪽) |
|---|---|
| 피부 | 밝은 피부 -> 보통 피부 -> 진한 피부 |
| 머리 | 단발 · 흑발 -> 단발 · 밤색 -> 뾰족 · 흑발 -> 뾰족 · 밤색 -> 뾰족 · 민트 -> 긴머리 · 분홍 -> 긴머리 · 금발 |
| 눈 | 기본 눈 -> 웃는 눈 -> 졸린 눈 -> 반짝 눈 |
| 상의 | 빨간 티셔츠 -> 파란 후드티 -> 파란 멜빵 -> 버섯 망토 |
| 하의 | 네이비 반바지 -> 청바지 -> 분홍 치마 -> 초록 호박바지 |

옵션 순서와 id는 `style-guide.md` 5.10과 같다. 화면은 매니페스트 순서를 그대로 따른다 (하드코딩 목록은 매니페스트 로딩 실패 시 대체로만 쓴다).

### 5.3 행 규격

- 행 높이 56px (모바일), 60px (데스크톱). 행 사이 구분선: 2px `c2` 실선 (`border-bottom: 2px solid #F2DDB8`), 마지막 행은 없음.
- 왼쪽 라벨: `fs-sm` 14px 700 `--text`, 가로 48px 고정.
- 이전/다음 버튼: 44 x 44px, `button-secondary-*` 스킨 (style-guide 7.3). 가운데에 `icon-arrow.png` 2배 (8 x 14). 이전 버튼은 아이콘을 `transform: scaleX(-1)`.
- 가운데 값: `fs-md` 16px 700 `--text`, 가운데 정렬, 말줄임. 데스크톱만 아래에 `fs-xs` 12px 700 `--text-muted`로 "2 / 7" 순번.
- 버튼 눌림: `button-secondary-pressed` (아이콘 4px 아래로).
- 키보드: 행(`role="group"`)에 포커스가 있을 때 좌/우 방향키로 이전/다음. 행 포커스 표시는 style-guide 3.2 포커스 외곽선.
- 순환: 맨 앞에서 이전을 누르면 맨 뒤로, 맨 뒤에서 다음을 누르면 맨 앞으로.
- 버튼 `aria-label`: "이전 머리 모양", "다음 머리 모양" 식으로 파츠 이름을 넣는다.
- 값 변경 시 `aria-live="polite"` 영역에 "머리: 뾰족 · 흑발" 식으로 알린다.

### 5.4 동작

- 좌/우 누르면 옵션이 바뀌고 미리보기가 즉시 갱신된다.
- 길게 누르면 자동 반복은 없다.
- 파츠 변경은 닉네임 상태에 영향을 주지 않는다.

## 8. 완료 흐름 (v1과 같음)

1. 만들기 누름 -> 버튼 "만드는 중" (비활성), 전체 입력 비활성.
2. 서버에 `nickname`과 `avatar`(5개 키) 저장 요청.
3. 성공 -> 페이드 200ms -> 인게임 진입.
4. 실패 -> 7장 규칙대로 표시, 입력 복구.

저장 값 예시 (기본 조합):

```json
{ "nickname": "버섯이", "avatar": { "skin": "skin-light", "hair": "hair-round-black", "eyes": "eyes-dot", "top": "top-tee-red", "bottom": "bottom-shorts-navy" } }
```

## 9. 접근성

- 닉네임 필드는 `<label for>`로 연결한다. 상태 줄은 `aria-describedby`로 연결하고, 상태가 바뀌면 `aria-live="polite"`로 읽는다.
- 파츠 행은 `role="group"`과 라벨(`aria-labelledby`)로 묶는다.
- 미리보기 캔버스는 `aria-hidden="true"`. 파츠 값 글자가 같은 정보를 전달한다.
- 모든 버튼 터치 영역 44px 이상 (방향 버튼 32px은 투명 여백으로 44px 확보). 포커스 외곽선 2px `--focus` + 간격 2px.
- 색만으로 상태를 구분하지 않는다. 상태 줄의 문구와 아이콘(✓)을 함께 쓴다.
