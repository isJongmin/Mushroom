# 화면 설계: 캐릭터 생성

버전: 3.0 (2026-10-14, 사이클 3 블록 UI + 7개 파츠). 흐름, 닉네임 규칙, 상태, 오류 문구, 완료 흐름은 v1/v2와 같다. 바뀐 것: 2장(레이아웃), 3장(회전 미리보기), 5장(카테고리 탭 7개 + 아이템 슬롯 그리드 + 프리셋, 좌/우 파츠 행 폐기), 저장 값(7개 키).
참조: `docs/design/style-guide.md` v3 (컴포넌트 5.12 슬롯, 5.13 프리셋, 5.14 미리보기), 구현 CSS `docs/design/ui-kit.css`, 아바타 데이터/매니페스트/레이어는 ARCHITECTURE "인터페이스 계약", "블록 아트 계약".
시안: `docs/design/ref/c3/create-desktop.png` (1280x800), `create-mobile.png` (360x640 첫 화면), `create-mobile-full.png` (전체 길이, sticky 버튼이 캡처 위치에 걸려 보임). 모자 슬롯(없음 포함) 모양은 `kit-desktop.png`.

## 1. 목적과 진입 (v1과 같음)

- 계정당 캐릭터 1개. 캐릭터가 없는 계정만 이 화면에 들어온다.
- 진입 경로: 회원가입 성공, 캐릭터 없는 계정으로 로그인.
- 완료 후: 인게임 (`game.md`)으로 이동.
- 이 화면을 떠나는 방법: "로그아웃" 버튼 (로그인 화면으로).

## 2. 레이아웃

### 2.1 공통

- 배경: 로그인과 같은 `.bk-world` (`login.md` 2.1). 로그인에서 넘어오면 그대로 둔다.
- 카드: `.bk-panel.card-create` (style-guide 5.1).
- 카드 맨 위 줄 `.card-head`: 왼쪽 제목 "캐릭터 만들기" (20px 700 `ink`, `<h1>`), 오른쪽 "로그아웃" 작은 보조 버튼(`.bk-btn--sm`, 높이 32, 터치 44). 아래 16px.
- 본문 `.create-grid`: 네 영역 `prev`(미리보기 + 방향 버튼), `parts`(프리셋 + 탭 + 슬롯), `nick`(닉네임), `cta`(만들기 버튼). CSS `grid-template-areas`로 배치만 바꾸고 DOM 순서는 prev → parts → nick → cta.
- LOCAL MODE 줄 (local 모드만): 카드 맨 아래 `.card-foot`, 위 16px.

### 2.2 데스크톱 (720px 이상)

카드 박스 가로 800px, 패딩 16px, 세로 가운데 (길면 위 32px부터).

| 열 | 가로 | 내용 (위 -> 아래) |
|---|---|---|
| 왼쪽 | 240px | `prev`: 미리보기(4배, 틀 포함 232 x 296) → 12px → 방향 버튼 줄(앞/옆/뒤 + 걷기) → 16px → `nick` → 16px → `cta` (가로 240) |
| 오른쪽 | 나머지 (800 - 32 - 240 - 24 = 504px) | `parts`: "추천 조합" 소제목 → 프리셋 3열 → 16px → "꾸미기" 소제목 → 카테고리 탭 7칸 → 12px → 슬롯 그리드 (5열) → 8px → 현재 값 안내 줄 |

열 사이 24px. 소제목 `.section-title`: 14px 700 `w4`, 아래 8px.

### 2.3 모바일 (720px 미만, 최소 360px)

한 열. 카드 박스 가로 `100vw - 36px` (360 폭에서 324px), 패딩 12px → 내용 300px. 카드 위 32px.

순서 (위 -> 아래):
1. 제목 + 로그아웃
2. `prev`: 미리보기 3배(틀 포함 176 x 224) 왼쪽, 오른쪽 12px 옆에 방향 버튼 4개 세로(앞, 옆, 뒤, 걷기 / 각 높이 40, 간격 8, 가로 112)
3. `parts`: 프리셋 2열 x 3줄 → 카테고리 탭 7칸(칸 약 38px, 간격 4) → 슬롯 그리드 3열(88 x 3 + 4 x 2 = 272px, 왼쪽 정렬) → 현재 값 줄
4. `nick`: 닉네임 필드 + 상태 줄
5. `cta`: 만들기 버튼 (가로 100%). `position: sticky; bottom: 0;` 위 8px, 아래 10px `c1` 띠를 버튼 뒤에 깔아 뒤로 지나가는 내용이 비치지 않게 한다 (`.create-cta`)
6. LOCAL MODE 줄

가로 스크롤 금지.

## 3. 미리보기 (회전 + 걷기)

### 3.1 무대

| 항목 | 값 |
|---|---|
| 틀 | `.bk-well` (오목 베벨 4px + 패딩 4px) |
| 캔버스 | 아트 56 x 72, 정수 배율 `--pv`: 데스크톱 4 (224 x 288 CSS), 모바일 3 (168 x 216). 백킹 = CSS x dpr, 스무딩 끔 |
| 무대 그림 | style-guide 5.14: 하늘 `k3` / `k4` / `k5` 띠, y 62–71 잔디 타일, 발 그림자 y 64 x 21–34 `g3` |
| 아바타 | 프레임 왼쪽 위 (4, 4) → 기준점 (28, 64). 합성과 외곽선은 게임과 같은 파이프라인(ARCHITECTURE 레이어 순서 + 실루엣 외곽선) |
| 접근성 | 캔버스 `aria-hidden="true"`. 정보는 슬롯 이름, 현재 값 줄이 전달 |

### 3.2 방향 버튼과 걷기

| 버튼 | 모양 | 동작 |
|---|---|---|
| 앞 / 옆 / 뒤 | `.bk-tabs` 3칸 (`role="radiogroup"`, 각 `role="radio"` + `aria-checked`, 모양은 `aria-selected` 규칙과 같게). 높이 40 | 앞 = 프레임 `front`, 옆 = `side_idle`(오른쪽), 뒤 = `back`. 기본값 앞 |
| 걷기 | 보조 버튼 + 오른쪽 화살표 도트 아이콘, `aria-pressed` | 켜면 보기를 "옆"으로 바꾸고 `side_walk0~3`을 manifest 걷기 시간(ARCHITECTURE)으로 반복. 다시 누르면 멈추고 `side_idle`. 켜진 동안은 눌림 모양(2px 내려감, 베벨 반전) |

- 걷기 중에 "앞" 또는 "뒤"를 누르면 걷기를 끄고 그 방향으로 바꾼다.
- 방향/걷기는 저장하지 않는다 (미리보기 전용).
- `prefers-reduced-motion: reduce`: 기본값이 정지이므로 그대로. 사용자가 걷기를 직접 켜면 재생한다.
- 파츠를 바꾸면 다음 프레임부터 반영하고, 걷기 위상(프레임 번호)은 끊지 않는다.
- 로딩: 파츠 PNG를 불러오는 동안 무대 그림만 그리고 가운데에 로딩 점(`ink`). 실패한 레이어는 빼고 그린다(콘솔 경고 1회, 화면 오류 없음, 생성 가능).

## 4. 닉네임 입력 (v1과 같음, 모양만 블록)

### 4.1 필드

| 항목 | 값 |
|---|---|
| 라벨 | "닉네임" (14px 700) |
| 입력 | `.bk-input` 박스 높이 44px, 16px, `maxlength="12"`, `autocomplete="off"`, `spellcheck="false"` |
| 허용 문자 | 한글 완성형 (가-힣), 영문 대소문자, 숫자 |
| 검사 정규식 | `^[가-힣a-zA-Z0-9]{2,12}$` |
| 도움말 (기본 상태) | "2~12자, 한글, 영문, 숫자만 사용할 수 있습니다." (12px 700 `w3`) |

규칙:
- 한글 자모(ㄱ, ㅏ 등 조합 중이거나 낱자)는 완성형이 아니므로 형식 오류로 처리한다.
- 공백, 특수문자, 이모지 금지. 입력 시 공백을 막지 않고 형식 오류로 알린다.
- 대문자와 소문자는 구분하지 않고 중복 판단한다 (서버 기준). 클라이언트 중복 판단은 서버 응답에 따른다.
- 입력 값 앞뒤 공백은 제거하고 검사한다.

### 4.2 상태 줄 (닉네임 필드 아래 4px, 높이 20px 고정)

높이는 항상 20px로 고정해 상태가 바뀌어도 화면이 흔들리지 않는다. 글자 12px 700.

| 상태 | 조건 | 글자 색 | 문구 | 아이콘 |
|---|---|---|---|---|
| 미확인 | 형식은 맞지만 아직 확인 안 함 | `w3` | "중복 확인이 필요합니다." | 없음 |
| 형식 오류 | 정규식 불일치 | `r3` | "2~12자의 한글, 영문, 숫자만 사용할 수 있습니다." | 없음 |
| 확인 중 | 중복 확인 요청 중 | `w3` | "확인 중..." | 로딩 점 (`.bk-dots`) |
| 사용 가능 | 서버 응답: 사용 가능 | `g4` | "사용할 수 있는 닉네임입니다." | 체크 도트 아이콘 `.bk-ico--check` (글리프 ✓ 대신) |
| 중복 | 서버 응답: 이미 사용 중 | `r3` | "이미 사용 중인 닉네임입니다." | 없음 |
| 확인 실패 | 네트워크 또는 서버 오류 | `r3` | "닉네임 확인에 실패했습니다. 다시 시도하세요." | 없음 |

입력 모양: 기본/포커스는 style-guide 5.4. 형식 오류 또는 중복이면 `aria-invalid="true"`(빨간 테두리). 사용 가능은 기본 모양 그대로(상태 줄로 표시).

### 4.3 중복 확인 시점 (v1과 같음)

- 값이 형식에 맞고 입력이 500ms 멈추면 자동 확인 (디바운스 500ms).
- 필드에서 포커스가 떠날 때 (blur), 형식이 맞고 아직 현재 값으로 확인하지 않았다면 즉시 확인.
- 값이 바뀌면 상태는 "미확인"으로 돌아간다. 이전 결과를 현재 값에 재사용하지 않는다.
- 만들기 버튼을 눌렀을 때 상태가 "사용 가능"이 아니면 확인부터 하고, 사용 가능이면 바로 생성 요청을 보낸다.
- 확인 응답은 참고용이다. 최종 중복 판단은 생성 요청 시 서버가 한다 (`409` 같은 중복 응답 -> "중복" 상태).

## 5. 파츠 선택 (카테고리 탭 + 슬롯 그리드 + 프리셋)

### 5.1 카테고리 탭 7개

| 순서 | 탭 글자 | avatar 키 | manifest `parts` 키 | "없음" 허용 |
|---|---|---|---|---|
| 1 | 피부 | `skin` | `skin` | 아니오 |
| 2 | 얼굴 | `face` | `face` | 아니오 |
| 3 | 머리 | `hair` | `hair` | 아니오 |
| 4 | 모자 | `hat` | `hat` (첫 항목 `none` "없음") | 예 |
| 5 | 상의 | `top` | `top` | 아니오 |
| 6 | 하의 | `bottom` | `bottom` | 아니오 |
| 7 | 신발 | `shoes` | `shoes` | 아니오 |

- 모양: `.bk-tabs.bk-tabs--cat` (7칸 같은 너비, 간격 4px, 높이 40px + 터치 확장 44px, 14px). 활성 = 잔디 눌림, 비활성 = 돌 블록.
- 접근성: `role="tablist"`, 각 `role="tab"` + `aria-selected` + `aria-controls`(슬롯 그리드). 좌/우 방향키로 탭 이동(roving tabindex), Home/End 처음/끝.
- 첫 진입 시 활성 탭 = 머리 (가장 많이 바꾸는 파츠). 탭을 바꿔도 선택 값은 유지된다.

### 5.2 슬롯 그리드 (style-guide 5.12)

- `.bk-slots`, `role="radiogroup"`, `aria-labelledby` = 활성 탭. 항목 순서 = manifest `parts[키]` 순서 (첫 항목이 기본값).
- 슬롯 `.bk-slot` 88 x 88, `role="radio"`, `aria-checked`, `aria-label` = manifest `label`. 썸네일 80 x 80 (style-guide 5.12 합성/자르기 표). 모자 `none`은 X 표시.
- 선택 슬롯: 노란 바탕 + 주황 테두리 + 오른쪽 위 잔디 블록 표식.
- 동작: 클릭/탭, Enter, Space → 선택. 방향키(←→↑↓)로 그리드 안 이동 + 선택(radio 동작, roving tabindex). 선택 즉시 미리보기 갱신.
- 현재 값 줄 (그리드 아래 8px, `.bk-help`, `aria-live="polite"`): "머리: 검은 짧은 머리" 식으로 `<탭 글자>: <label>`.
- 썸네일은 외형(피부, 현재 머리)이 바뀌면 다시 만든다. 만들기 전에는 슬롯 바탕만 보이고 이름은 `aria-label`로 전달된다.
- 매니페스트 로딩 실패: 탭과 그리드 자리에 오류 배너 "파츠 정보를 불러오지 못했습니다. 새로고침해 주세요." 를 띄우고 만들기 버튼을 비활성 (아바타 없이 생성하지 않음).

### 5.3 프리셋 (style-guide 5.13)

- "추천 조합" 소제목 아래, manifest `presets` 배열 순서대로 버튼 (현재 6종: 후드 소년, 분홍 소녀, 모자 소년, 버섯 꼬마, 하늘 마법사, 탐험가). 데스크톱 3열, 모바일 2열. 개수가 바뀌면 줄 수만 바뀐다.
- 버튼: 높이 48, 40x40 머리 썸네일 + `label` (style-guide 5.13).
- 누르면 7개 값을 프리셋 `avatar`로 덮어쓴다. manifest에 없는 id는 그 파츠 기본값으로. 활성 탭은 그대로, 슬롯 선택 표시와 미리보기 즉시 갱신. 현재 값 줄에 "추천 조합 적용: <label>".
- 프리셋은 선택 상태를 유지하지 않는다 (적용 후 슬롯을 바꾸는 것이 자연스러운 흐름).

### 5.4 초기값

- 7개 키 모두 manifest 각 파츠의 첫 항목 (모자는 `none`).
- 파츠 변경은 닉네임 상태에 영향을 주지 않는다.

| `NICK_TAKEN` | 닉네임 중복 (확인 또는 생성 응답) | 닉네임 상태 줄 | 이미 사용 중인 닉네임입니다. |
| `NICK_CHECK_FAILED` | 중복 확인 실패 | 닉네임 상태 줄 | 닉네임 확인에 실패했습니다. 다시 시도하세요. |
| `NETWORK` | 생성 요청 실패 (네트워크) | 카드 상단 오류 배너 (`.bk-banner--error`, `role="alert"`), 제목 줄 아래 | 캐릭터를 만들지 못했습니다. 연결을 확인한 뒤 다시 시도하세요. |
| `SERVER` | 그 밖의 생성 실패 | 카드 상단 오류 배너 | 캐릭터를 만들지 못했습니다. 잠시 후 다시 시도하세요. |
| `MANIFEST` | 파츠 매니페스트 로딩 실패 (신규) | 파츠 영역 오류 배너 | 파츠 정보를 불러오지 못했습니다. 새로고침해 주세요. |

규칙:
- 생성 실패 후에도 입력한 닉네임과 파츠 선택은 유지된다.
- 배너는 다음 생성 요청 시 지운다.

## 8. 완료 흐름

1. 만들기 누름 -> 버튼 "만드는 중" (비활성), 전체 입력 비활성.
2. 서버에 `nickname`과 `avatar`(7개 키, ARCHITECTURE 인터페이스 계약) 저장 요청.
3. 성공 -> 페이드 200ms -> 인게임 진입.
4. 실패 -> 7장 규칙대로 표시, 입력 복구.

저장 값 예시 (id는 `assets/avatar/manifest.json` 기준. 아래는 프리셋 "후드 소년"):

```json
{ "nickname": "버섯이",
  "avatar": { "skin": "light", "face": "basic", "hair": "black-short", "hat": "none",
              "top": "hoodie-black", "bottom": "pants-navy", "shoes": "sneakers-white" } }
```

## 9. 접근성

- 닉네임 필드는 `<label for>`로 연결한다. 상태 줄은 `aria-describedby`로 연결하고, 상태가 바뀌면 `aria-live="polite"`로 읽는다.
- 탭(`tablist`) → 슬롯(`radiogroup`) → 현재 값 줄(`aria-live`)로 같은 정보를 글자로 전달한다. 미리보기 캔버스는 `aria-hidden`.
- 방향 버튼은 `radiogroup`, 걷기는 `aria-pressed`.
- Tab 순서: 로그아웃 → 방향(앞/옆/뒤 묶음 1개) → 걷기 → 프리셋들 → 카테고리 탭(묶음 1개) → 슬롯 그리드(묶음 1개) → 닉네임 → 만들기.
- 모든 버튼 터치 영역 44px 이상 (로그아웃 32px과 탭 40px은 투명 확장으로 44px). 포커스 외곽선 2px `u3` + 간격 4px.
- 색만으로 상태를 구분하지 않는다: 선택 슬롯은 테두리 두께와 표식, 상태 줄은 문구와 아이콘.

## 10. 360px 체크 항목 (QA)

- [ ] 가로 스크롤 없음. 카드 박스 324px, 내용 300px.
- [ ] 미리보기 3배(168 x 216) 오른쪽에 방향 버튼 4개가 세로로 있고 겹치지 않는다.
- [ ] 카테고리 탭 7칸이 한 줄에 들어가고 글자가 잘리지 않는다.
- [ ] 슬롯 그리드가 3열(88px)이고 선택 슬롯의 바깥 테두리가 잘리지 않는다. 머리 8종이 3줄로 보인다.
- [ ] 앞/옆/뒤 버튼으로 front/side/back 프레임이 바뀌고, 걷기를 켜면 옆모습으로 4프레임 걷는다.
- [ ] 프리셋을 누르면 7개 파츠가 한 번에 바뀌고 해당 슬롯 선택 표시가 따라간다.
- [ ] sticky 만들기 버튼 뒤로 내용이 지나갈 때 글자가 겹쳐 보이지 않는다 (`c1` 띠).
- [ ] LOCAL MODE 칩이 카드 안 맨 아래에 있고 어떤 스크롤 위치에서도 다른 요소와 겹치지 않는다.
