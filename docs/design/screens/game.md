# 화면 설계: 인게임 (맵 + HUD)

버전: 2.0 (2026-10-14, 사이클 2 픽셀 스킨). 조작, 채팅 규칙, 접속자 수 규칙, 재연결 규칙, 접근성은 v1과 같다. 바뀐 것: 1장 구성, 2·3장 레이아웃(캔버스 크기, HUD 겹침 배치), 6장 아바타 표시(프레임 애니메이션), 7장 배너 스킨, 10장 체크 항목.
참조: `docs/design/style-guide.md` (배율과 카메라 4장, 아바타 5장, 맵 6장, UI 스킨 7장, 닉네임 라벨 8장, 말풍선 9장). 실시간 메시지 형식은 ARCHITECTURE 4번 결정을 따른다.
시안: `docs/design/ref/map-draft.png` (데스크톱 P=2, 960 x 540 부분).

## 1. 구성

| 영역 | 내용 | 구현 방식 |
|---|---|---|
| 게임 캔버스 | 맵 레이어 7개, 발 그림자, 아바타, 닉네임 라벨, 말풍선 | Canvas 2D (style-guide 4.4 파이프라인) |
| HUD (캔버스 위에 겹침) | 접속자 배지, LOCAL MODE 칩, 조작 힌트 (데스크톱), 로그아웃, 상태 배너 | DOM, 캔버스와 같은 크기의 `position: relative` 래퍼 안에 `position: absolute` |
| 채팅 입력 | 입력 필드, 글자 수, 전송 버튼 (모바일) | DOM, 캔버스 아래 |
| 터치 버튼 | 왼쪽 이동, 오른쪽 이동 (모바일) | DOM, 캔버스 아래 |

채팅 기록 패널은 없다. 채팅은 말풍선으로만 보이고 저장하지 않는다 (ARCHITECTURE 4번).
페이지 바탕(캔버스 바깥)은 `--letterbox` (`#1A1626`).

## 2. 데스크톱 레이아웃 (720px 이상)

세로 묶음 [캔버스 → 12px → 채팅 입력 행 44px → 16px]을 뷰포트 가로 가운데, 세로 가운데에 둔다.

| 요소 | 위치 | 규격 |
|---|---|---|
| 캔버스 | 묶음 맨 위 | style-guide 4.2: P=2이면 가로 `min(innerWidth, 1280)`, 세로 `min(540, innerHeight - 72)` (각각 P의 배수로 내림). P=3 조건이면 최대 1920 x 810 |
| 접속자 배지 | 캔버스 왼쪽 위, 여백 12px | `chip.png` 스킨 (style-guide 7.5). `icon-mushroom` 2배 (18 x 16) + 4px + "접속 중 N명" `fs-sm` 14px 700 `ink`. 높이 28px |
| LOCAL MODE 칩 | 접속자 배지 오른쪽 8px, 세로 가운데 | style-guide 7.9. local 모드만 |
| 조작 힌트 | 캔버스 오른쪽 위, 로그아웃 버튼 왼쪽 8px | `chip.png` 스킨, 글자 `fs-xs` 12px 700 `--text-muted`, 높이 28px. 내용: "← → 또는 A D 이동 · Enter 채팅 · Esc 입력 해제". 캔버스 가로 900px 미만이면 숨긴다 (배지와 겹침 방지) |
| 로그아웃 버튼 | 캔버스 오른쪽 위, 여백 12px | 작은 보조 버튼 (`button-secondary-*`), 높이 32px, 가로 패딩 8px, 글자 `fs-sm` 14px 700 `ink` |
| 상태 배너 | 캔버스 위 가운데, 위에서 52px | 7장 |
| 채팅 입력 행 | 캔버스 아래 12px, 가운데 | 가로 `min(560px, 캔버스 가로 - 32px)`, 높이 44px, 입력 스킨 (style-guide 7.4) |

HUD 요소는 캔버스의 아래쪽 60px(지면 아래 흙 영역, 닉네임 라벨 자리)에 두지 않는다.

### 2.1 채팅 입력 (데스크톱)

- 입력 필드: 가로 100%, 높이 44px, `input-normal` / `input-focus` 스킨, 글자 `fs-md` 16px 400. 플레이스홀더: "메시지를 입력하세요" (`--text-muted`).
- 글자 수 표시: 입력 오른쪽 안쪽 (스킨 테두리 안 4px). 형식 "N/80", `fs-xs` 12px 700 `--text-muted`. 입력 시작 후에만 표시.
- `maxlength="80"`. 81번째 글자는 입력되지 않는다.
- 전송 버튼 없음 (Enter로 전송, v1과 같음).

## 3. 모바일 레이아웃 (720px 미만, 최소 360px)

세로 순서 (위 -> 아래). 기준 360 x 640.

| 순서 | 요소 | 높이 | 규격 |
|---|---|---|---|
| 1 | 게임 캔버스 | `innerHeight - 124` (P=2의 배수로 내림) | 가로 = 화면 폭 전체 (좌우 여백 없음, 테두리 없음). 360 x 640에서 360 x 516 CSS = 시야 180 x 258 아트 px |
| 2 | 좌/우 터치 버튼 행 | 8 + 56 | 위 여백 8px, 좌우 여백 16px. 두 버튼 가로 50% (간격 8px), 높이 56px, `button-secondary-*` 스킨. 내용: 왼쪽 버튼 [◀ 아이콘(`icon-arrow` 반전) 8px "왼쪽"], 오른쪽 버튼 ["오른쪽" 8px ▶ 아이콘], 글자 `fs-md` 16px 700 `ink` |
| 3 | 채팅 입력 행 | 8 + 44 + 8 | 위아래 여백 8px, 좌우 16px. 입력 필드 (가로 나머지, `input-*` 스킨) + 8px + 전송 버튼 "보내기" (가로 72px, 높이 44px, `button-primary-*`) |

- 아래 조작 영역 합계 124px. 캔버스가 나머지 세로를 모두 써서 하단 빈 공간이 생기지 않는다 (사이클 1 QA 해결).
- HUD (캔버스 위 겹침):
  - 왼쪽 위 (8, 8): 접속자 배지 (데스크톱과 같은 칩) + 8px + LOCAL MODE 칩 (local 모드만).
  - 오른쪽 위 (8, 8): 로그아웃 작은 보조 버튼 (높이 32px, 위아래 6px 투명 여백으로 터치 44px).
  - 조작 힌트는 표시하지 않는다.
  - 360px에서 배지(약 120px) + 칩(약 76px) + 로그아웃(약 72px) + 여백 = 약 300px로 한 줄에 들어간다.
- 카메라: style-guide 4.3 (화면 아래 끝 = 아트 y 250, 위쪽 넘침은 `k1`). 닉네임 라벨이 캔버스 안에 들어온다 (사이클 1 QA 해결).
- 소프트 키보드: `visualViewport.height`로 캔버스 세로를 다시 계산한다 (`visualViewport.height - 124`, 최소 160px). 캔버스가 위에서부터 줄어들고 채팅 입력 행은 키보드 바로 위에 남는다.

### 3.1 터치 버튼 동작 (v1과 같음)

- `pointerdown` -> 해당 방향 이동 시작. `pointerup`, `pointercancel`, `pointerleave` -> 정지.
- 두 버튼을 동시에 누르면 나중에 누른 쪽이 우선. 한쪽을 떼면 남은 쪽 방향으로 이동을 계속한다 (누르고 있는 상태일 때만).
- CSS: `touch-action: none; user-select: none; -webkit-user-select: none;` 버튼에 적용.
- 누르는 동안: `button-secondary-pressed` 스킨 (내용 4px 아래로).

### 3.2 모바일 전송 버튼

- 기본 `button-primary-normal`, 누름 `button-primary-pressed`, 글자 "보내기" `fs-md` 16px 700 `ink`.
- 빈 입력 또는 쿨다운 중: `button-primary-disabled`, 글자 `--text-muted`.

## 4. 접속자 수 (v1과 같음)

| 항목 | 규칙 |
|---|---|
| 숫자 | 실시간 Presence에 있는 사용자 수 (나 포함) |
| 표시 | 1명 ~ 999명: "접속 중 N명". 1000명 이상: "접속 중 999명+" |
| 갱신 | Presence 동기화 때마다 갱신. 깜빡임 없이 숫자만 바꾼다 |
| 연결 끊김 중 | 마지막 숫자 유지, 글자 뒤에 4px 간격으로 6 x 6px 정사각형 점 (`--text-muted`) 표시 |

## 5. 채팅 입력 동작 (v1과 같음)

### 5.1 키보드

| 키 | 입력 포커스가 없을 때 | 입력 포커스가 있을 때 |
|---|---|---|
| Enter | 채팅 입력으로 포커스 이동 | 전송 (빈 값이면 무시, 한글 조합 중이면 무시) |
| Esc | 아무 동작 없음 | 포커스 해제 (게임으로 복귀). 입력 내용은 남긴다 |
| ← 또는 A | 왼쪽 이동 (누르고 있는 동안) | 입력 문자로 처리 (이동 안 함) |
| → 또는 D | 오른쪽 이동 (누르고 있는 동안) | 입력 문자로 처리 (이동 안 함) |

규칙:
- 입력에 포커스가 있으면 이동 키는 게임에 전달되지 않는다.
- 두 방향 키를 동시에 누르면 나중에 누른 방향으로 이동한다. 한쪽을 떼면 남은 키 방향으로 이동을 계속한다.
- 창이 포커스를 잃으면 (`blur`) 이동을 멈추고 눌림 상태를 초기화한다.
- 키 반복 입력(`repeat`)은 무시하고 누름 상태만 본다.

### 5.2 전송 규칙

| 항목 | 규칙 |
|---|---|
| 앞뒤 공백 | 전송 전 제거 (`trim`) |
| 빈 값 | 전송하지 않는다. 오류 표시 없음 |
| 길이 | 최대 80자. 입력 필드가 막는다 (`maxlength="80"`) |
| 전송 간격 | 1초에 1회 (쿨다운 1000ms). 쿨다운 중 전송 시도는 무시하고 아래 힌트를 0.8초 표시 |
| 쿨다운 힌트 | 채팅 입력 행 바로 위 8px, 가운데. `chip.png` 스킨, 글자 `fs-xs` 12px 700 `--text-muted`, "1초 뒤에 다시 보낼 수 있습니다." (데스크톱은 캔버스 아래쪽에 겹쳐 보인다) |
| 전송 성공 | 입력 내용 비우기. 포커스 유지 (계속 채팅 가능) |
| 전송 실패 | 입력 내용 유지. 쿨다운 힌트와 같은 자리에 오류 칩 (style-guide 7.11 오류 배너 모양, 글자 `fs-xs` 12px) "메시지를 보내지 못했습니다." 2초 뒤 사라짐. `role="alert"` |
| 내 말풍선 | 내가 보낸 메시지도 내 캐릭터 위 말풍선으로 바로 보인다 (서버 왕복 기다리지 않음) |

설계 메모: 1초 쿨다운은 디자인이 추가한 클라이언트 제한이다 (ARCHITECTURE에 채팅 빈도 제한 없음).

### 5.3 IME (한글 입력)

- Enter를 눌러 조합이 끝나는 중이면 (`isComposing`) 전송하지 않는다.
- 조합 중 글자 수 카운터는 조합 중인 글자까지 센다 (브라우저 값 기준).

## 6. 아바타와 말풍선 표시

| 항목 | 규칙 |
|---|---|
| 아바타 | style-guide 5장. 32 x 48 프레임, 기준점 (16,46)을 월드 `(x, 440)` = 아트 `(round(x/2), 220)`에 맞춘다 |
| 애니메이션 | 이동 중 walk (120ms x 4), 정지 idle (500ms x 2). 상태가 바뀌면 첫 프레임부터. 다른 사용자는 style-guide 5.11 판정 |
| 방향 | 이동 방향으로 좌우 반전. 정지 시 마지막 방향 유지. 다른 사용자는 `move.dir` |
| 발 그림자 | style-guide 4.5 3번 (아바타보다 먼저) |
| 그리기 순서 | 다른 사용자 (월드 x 오름차순) → 내 캐릭터 마지막 |
| 닉네임 라벨 | style-guide 8장. 내 캐릭터는 `label-self` (주황), 다른 사람 `label-other` (짙은 남색) |
| 말풍선 | style-guide 9장. 5초 표시, 마지막 0.5초 페이드 |
| 말풍선 줄 수 | 최대 4줄. 넘치면 `…`으로 자른다 |
| 파츠 id | 예전 id와 없는 id는 style-guide 5.10 표대로 바꿔 그린다 |

사이클 1의 "이동 중 상하 2px, 0.4초 흔들림"은 폐기 (프레임 애니메이션이 대신한다).

## 7. 상태와 배너

### 7.1 상태 표

| 상태 | 캔버스 | HUD | 배너 (캔버스 위 가운데) |
|---|---|---|---|
| 입장 중 (에셋 로딩 + 채널 접속) | `--letterbox` 색 + 가운데 로딩 점 (`login.md` 5.1, 색 `c1`) | 숨김 | 정보 배너 "마을에 들어가는 중..." |
| 정상 | 게임 진행 | 표시 | 없음 |
| 연결 끊김 (재연결 중) | 마지막 프레임 유지, 아바타 이동 멈춤 (idle 애니메이션은 계속) | 표시 (접속자 점 표시) | 오류 배너 "연결이 끊어졌습니다. 다시 연결하는 중..." (`role="status"`) |
| 재연결 실패 | 마지막 프레임 유지 | 로그아웃만 조작 가능 | 오류 배너 "연결하지 못했습니다." + 오른쪽 8px에 작은 주 버튼 "다시 연결" (높이 32px) |
| 치명적 오류 | `--letterbox` 색 | 숨김 (로그아웃만 표시) | 오류 배너 "마을에 들어갈 수 없습니다. 다시 시도하세요." + 작은 주 버튼 "다시 시도" |
| 에셋 일부 실패 | 맵 레이어 실패: 그 레이어만 빼고 그림 (`k1` 바탕). 파츠 실패: 그 레이어만 빼고 그림 | 표시 | 없음 (콘솔 경고 1회) |

재연결 규칙 (v1과 같음):
- 끊김 감지 후 자동 재연결을 최대 3회 시도한다. 간격 1초, 2초, 4초.
- 3회 실패하면 "재연결 실패" 상태.
- 재연결 성공 시 배너를 0.5초 뒤 지운다 (페이드).

### 7.2 배너 규격

- 모양: style-guide 7.11 (정보 = `chip.png` 스킨, 오류 = 분홍 바탕 + `r3` 2px 테두리 + 2px 아래 립).
- 가로 `auto`, 최대 `min(480px, 캔버스 가로 - 32px)`. 글자 `fs-sm` 14px 700, 가운데 정렬, 줄바꿈 허용.
- 위치: 캔버스 위 가운데, 캔버스 위에서 52px (데스크톱) / 48px (모바일) (HUD 첫 줄 아래).

## 8. 로그아웃 (v1과 같음)

- 누르면 실시간 채널에서 나가고 세션을 끊은 뒤 로그인 화면 (`login.md`)으로 이동.
- 확인 창 없음 (MVP). 채팅 입력 중이었다면 입력은 버린다.
- 전환은 페이드 200ms. 로그인 화면의 배경 맵 캔버스를 새로 만든다.

## 9. 포커스와 접근성 (v1과 같음)

- 게임 캔버스는 `tabindex="0"`이고 `aria-label="버섯마을 맵. 좌우 방향키로 이동, Enter로 채팅"`.
- 키보드 포커스는 캔버스에 있어야 이동 키가 동작한다. 캔버스를 누르면 캔버스로 포커스가 간다.
- 포커스 표시: `outline: 2px solid var(--focus); outline-offset: -4px` (캔버스는 바깥 공간이 없을 수 있어 안쪽에 그린다). 다른 요소는 style-guide 3.2.
- 말풍선 내용은 `aria-live`로 읽지 않는다 (채팅 스팸 방지). 채팅 전송 실패만 `role="alert"`.
- 터치 버튼과 전송 버튼 44px 이상.
- 색만으로 상태를 구분하지 않는다. 배너와 접속자 점에는 문구가 있다.

## 10. 360 x 640 체크 항목 (QA)
