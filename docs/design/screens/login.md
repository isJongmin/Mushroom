# 화면 설계: 로그인 / 회원가입

버전: 2.0 (2026-10-14, 사이클 2 픽셀 스킨). 화면 흐름, 입력 규칙, 오류 문구, 상태, 동작은 v1과 같다. 바뀐 것은 2장(레이아웃), 2.5(필드 스킨), 5장(버튼과 로딩 표시)이다.
참조: `docs/design/style-guide.md` (팔레트 1장, 글자 2장, UI 스킨 7장, 맵 6장). 인증은 ARCHITECTURE 3번 결정을 따른다 (아이디 → `<아이디>@mushroom.local` 매핑은 화면에 드러내지 않는다).
시안: `docs/design/ref/login-desktop.png`, `docs/design/ref/login-mobile.png`.

## 1. 목적과 진입

- 앱 첫 화면. 세션이 있으면 건너뛴다 (로그인 상태이면 2단계 판정으로 이동).
- 로그인 성공 후 분기:
  - 캐릭터가 있으면 -> 인게임 (`game.md`)
  - 캐릭터가 없으면 -> 캐릭터 생성 (`character-create.md`)
- 회원가입 성공 후: 항상 캐릭터 생성으로 이동한다 (신규 계정은 캐릭터가 없다).

## 2. 레이아웃

### 2.1 배경: 마을 맵 재사용

| 항목 | 값 |
|---|---|
| 요소 | 화면 전체를 덮는 `<canvas class="bg-map">` (`position: fixed; inset: 0; z-index: 0; pointer-events: none;`, `aria-hidden="true"`) |
| 내용 | 게임 맵 레이어(`assets/map/manifest.json`) 전부. 아바타, 라벨, 말풍선 없음 |
| 배율과 카메라 | style-guide 4.2 P 규칙 (모바일 2, 데스크톱 2, 큰 화면 3). 캔버스 크기 = 뷰포트 전체 (P의 배수로 내림). 세로 카메라 = style-guide 4.3 (`camY = 250 - viewH`, 위쪽 넘침은 `k1`) |
| 자동 이동 | `camX`가 0 ↔ `1200 - viewW` 사이를 초당 10 아트 px로 왕복 (끝에서 바로 반대 방향). 정수 아트 px 단위로만 움직인다 |
| 동작 줄이기 | `prefers-reduced-motion: reduce`이면 `camX = 300` 고정 |
| 로딩 전 / 실패 | `body` 바탕 `k1` (`#6EC6F5`)만 보인다. 맵 PNG가 모두 로드되면 캔버스를 200ms 페이드 인. 실패하면 `k1` 바탕 그대로 (오류 표시 없음, 콘솔 경고 1회) |
| 탭 숨김 | `document.hidden`이면 그리기를 멈춘다 |

캐릭터 생성 화면도 같은 배경 컴포넌트를 쓴다. 화면 전환 때 배경은 다시 만들지 않고 유지한다 (카메라 위치 이어짐).

### 2.2 로고 (패널 위)

- 한 줄: `icon-mushroom.png` 4배 (36 x 32) + 8px 간격 + "버섯마을" `fs-xl` 32px 800.
- 글자색 `c1`, `text-shadow`: `w4` 2px 8방향 외곽 + `0 4px 0 #5E3620` (style-guide 2.3).
- 패널과 간격 16px. 가운데 정렬. `<h1>`.

### 2.3 데스크톱 (720px 이상)

- 로고 + 패널 묶음을 뷰포트 세로 가운데에 둔다 (묶음이 뷰포트보다 길면 위 32px부터 시작하고 페이지 스크롤).
- 패널 가로 360px 고정 (스킨 테두리 포함).

### 2.4 모바일 (720px 미만, 최소 360px)

- 로고 위 여백 32px, 패널 가로 = 뷰포트 폭 - 32px (좌우 16px).
- 내용이 길면(회원가입 모드) 페이지가 세로로 스크롤된다. 배경 캔버스는 고정이라 같이 움직이지 않는다.
- 가로 스크롤 금지.

### 2.5 패널 (`.px-panel`, style-guide 7.2)

- 스킨 테두리 16px + 안쪽 여백 8px = 내용은 바깥 끝에서 24px 안쪽.
- 내부 순서 (위 -> 아래):

| 순서 | 요소 | 규격 |
|---|---|---|
| 1 | 부제 "친구들과 함께 노는 작은 마을" | `fs-sm` 14px 700, `--text-strong` (`w4`), 가운데 정렬 |
| 2 | 탭 (세그먼트) | 높이 40px, 두 버튼 가로 (전체 - 8px) / 2, 간격 8px. 활성: `button-primary-pressed` 스킨, 글자 `ink`. 비활성: `button-secondary-normal`, 글자 `--text-muted`, 호버 `button-secondary-hover`. 부제와 16px 간격 |
| 3 | 오류 배너 (있을 때만) | style-guide 7.11 오류 배너. `role="alert"`. 탭과 16px 간격 |
| 4 | 아이디 필드 | 라벨 + 입력 + 도움말 + 필드 오류 |
| 5 | 비밀번호 필드 | 라벨 + 입력 + 도움말 + 필드 오류 |
| 6 | 비밀번호 확인 필드 (회원가입만) | 라벨 + 입력 + 필드 오류 |
| 7 | 제출 버튼 | 가로 100%, 높이 48px, 주 버튼 |
| 8 | LOCAL MODE 줄 (local 모드만) | style-guide 7.9. 제출 버튼 아래 16px, 가운데 정렬 |

필드 사이 간격 16px.

### 2.6 필드 규격

- 라벨: `fs-sm` 14px 700, `--text`. 입력 위 4px.
- 입력: 높이 44px, 가로 100%, 스킨 `input-normal` (style-guide 7.4), 글자 `fs-md` 16px 400 `--text`, 플레이스홀더 `--text-muted`.
- 포커스: `input-focus` 스킨 (파란 2px 테두리). 별도 outline 없음.
- 오류: `input-error` 스킨, `aria-invalid="true"`. 포커스 중이면 포커스 스킨이 우선이고 오류 문구는 계속 보인다.
- 비활성: `input-disabled` 스킨, 글자 `--text-muted`.
- 도움말: `fs-xs` 12px 700 `--text-muted`, 입력 아래 4px.
- 필드 오류: `fs-xs` 12px 700 `--error`, 입력 아래 4px. 도움말 자리를 대체한다.
- 비밀번호 "보기" 토글: 입력 오른쪽 안쪽 (스킨 테두리 안), 44 x 44 영역, 글자 `fs-sm` 14px 700 `u3`, 배경 없음. 누르면 `type`을 text/password로 바꾼다. `aria-pressed`로 상태를 알린다. 라벨 "보기" / "숨기기".

## 3. 입력 필드 (v1과 같음)

| 필드 | 모드 | 속성 | 검증 규칙 |
|---|---|---|---|
| 아이디 | 로그인, 회원가입 | `type="text"`, `autocomplete="username"`, `autocapitalize="none"`, `spellcheck="false"`, `maxlength="16"`, `inputmode="latin"` | 정규식 `^[a-z0-9_]{4,16}$`. 대문자 자동 변환 없음 (대문자는 형식 오류) |
| 비밀번호 | 로그인 | `type="password"`, `autocomplete="current-password"`, `maxlength="72"` | 검사 없음 (서버 판단). 빈 값만 막는다: 오류 문구 없이 제출 버튼 비활성 |
| 비밀번호 | 회원가입 | `type="password"`, `autocomplete="new-password"`, `maxlength="72"` | 8자 이상 (문자 수 기준). 공백 포함 여부는 허용 |
| 비밀번호 확인 | 회원가입 | `type="password"`, `autocomplete="new-password"`, `maxlength="72"` | 비밀번호와 완전 일치 |

도움말 문구: 아이디 "영문 소문자, 숫자, 밑줄(_) 4~16자", 비밀번호(회원가입) "8자 이상". 로그인 모드 비밀번호에는 도움말이 없다.

### 3.1 검증 시점

- 필드에서 포커스가 떠날 때 (blur): 해당 필드의 형식 검사. 틀리면 필드 오류 표시.
- 제출할 때: 모든 필드를 검사하고 첫 번째 오류 필드로 포커스를 옮긴다.
- 입력 중: 이미 표시된 오류는 값이 규칙을 통과하는 순간 지운다. 새 오류는 blur 또는 제출 때만 띄운다.
- 아이디 중복은 서버 응답으로만 확인한다 (입력 중 중복 확인 호출 없음).

## 4. 오류 문구 (v1과 같음, 정확히 이 문장을 사용)

| 코드 | 상황 | 표시 위치 | 문구 |
|---|---|---|---|
| `ID_FORMAT` | 아이디 형식 오류 (대문자, 특수문자, 3자 이하, 17자 이상, 한글) | 아이디 필드 아래 | 아이디는 영문 소문자, 숫자, 밑줄(_)을 사용해 4~16자로 입력하세요. |
| `PW_SHORT` | 비밀번호 8자 미만 (회원가입) | 비밀번호 필드 아래 | 비밀번호는 8자 이상 입력하세요. |
| `PW_MISMATCH` | 비밀번호 확인 불일치 (회원가입) | 비밀번호 확인 필드 아래 | 비밀번호가 일치하지 않습니다. |
| `ID_TAKEN` | 아이디 중복 (회원가입 응답) | 아이디 필드 아래 | 이미 사용 중인 아이디입니다. |
| `LOGIN_FAILED` | 로그인 실패 (아이디 없음 또는 비밀번호 틀림) | 상단 오류 배너 | 아이디 또는 비밀번호가 올바르지 않습니다. |
| `NETWORK` | 네트워크 오류 (요청 실패, 시간 초과, 오프라인) | 상단 오류 배너 | 연결에 문제가 있습니다. 인터넷 연결을 확인한 뒤 다시 시도하세요. |
| `SERVER` | 그 밖의 서버 오류 | 상단 오류 배너 | 문제가 발생했습니다. 잠시 후 다시 시도하세요. |

규칙:
- `LOGIN_FAILED`는 아이디가 존재하는지 드러내지 않는다. 문구를 바꾸지 않는다.
- `LOGIN_FAILED` 발생 시 아이디는 유지하고 비밀번호 필드만 비운다. 비운 뒤 비밀번호 필드에 포커스를 준다.
- 배너 오류는 다음 제출 시 지운다. 필드 오류는 해당 값이 바뀌면 지운다.
- `ID_TAKEN`은 회원가입에서만 나온다. 로그인 모드에서 받으면 `LOGIN_FAILED`로 처리한다.

## 5. 상태

| 상태 | 제출 버튼 | 입력 | 탭 | 표시 |
|---|---|---|---|---|
| 기본 | 활성. 라벨 "로그인" 또는 "가입하고 시작하기" | 활성 | 활성 | 없음 |
| 필드 오류 | 활성 | 활성 (오류 필드는 `aria-invalid`, `input-error` 스킨) | 활성 | 필드 오류 문구 |
| 처리 중 | 비활성 스킨. 로딩 점 + "로그인 중" 또는 "가입 중" | 모두 비활성 (`disabled`, `input-disabled` 스킨) | 비활성 | 없음 |
| 배너 오류 | 활성 | 활성 | 활성 | 상단 오류 배너 |
| 완료 | 비활성 | 비활성 | 비활성 | 화면 전환 (패널만 페이드 200ms, 배경 유지) |

### 5.1 로딩 점 (픽셀 스피너 대체)

- 4 x 4px 정사각형 3개, 간격 4px, 색 `ink` (비활성 버튼 위에서는 `--text-muted`). 전체 20 x 4px.
- 하나씩 차례로 진해지는 애니메이션: 각 점이 300ms 동안 불투명 1, 나머지는 0.35. 900ms 주기. 계단식(`steps`)으로 바뀐다 (부드러운 전환 없음).
- `prefers-reduced-motion: reduce`이면 세 점 모두 불투명 1로 정지.
- 버튼 안에서는 글자 왼쪽 8px. `aria-hidden="true"`, 상태는 버튼 글자가 전달한다.
- 제출 중 Enter 연타로 두 번 요청하지 않는다.

### 5.2 버튼 규격 (style-guide 7.3)

- 높이 48px, 가로 100%.
- 기본 `button-primary-normal`, 호버 `button-primary-hover`, 누름 `button-primary-pressed` (글자 4px 아래로), 비활성 `button-primary-disabled`.
- 글자 `fs-md` 16px 700 `ink` + `white` 1px 그림자 (호버, 비활성은 그림자 없음, 비활성 글자 `--text-muted`).
- 포커스: `outline: 2px solid var(--focus); outline-offset: 2px`.

## 6. 동작 (v1과 같음)

| 동작 | 결과 |
|---|---|
| 탭 "로그인" 또는 "회원가입" 누름 | 모드 전환. 입력한 아이디는 유지. 비밀번호와 확인 값은 비운다. 모든 오류 지움. 확인 필드는 회원가입에서만 보인다 |
| 제출 (버튼 또는 비밀번호 필드에서 Enter) | 검사 -> 통과하면 요청. 실패하면 첫 번째 오류 필드로 포커스 |
| 아이디 필드에서 Enter | 비밀번호 필드로 포커스 이동 (제출하지 않음) |
| 제출 성공 (로그인) | 캐릭터 확인 후 인게임 또는 캐릭터 생성으로 이동 |
| 제출 성공 (회원가입) | 캐릭터 생성으로 이동 |
| 세션 확인 중 (앱 시작 직후) | 패널 자리에 패널 스킨(가로 동일, 높이 96px) + 가운데 로딩 점만 표시. 최대 3초. 넘으면 로그인 화면 표시 + `NETWORK` 배너 |

화면 전환은 페이드 200ms. 전환 중 뒤로가기는 로그인 화면으로 돌아오지 않게 한다 (히스토리 교체).

## 7. 접근성과 입력 세부 (v1과 같음)

- 모든 입력에 `<label for>`를 연결한다. 도움말과 오류는 `aria-describedby`로 연결한다.
- 배너 오류는 `role="alert"`. 필드 오류는 입력 바로 아래에 텍스트로 둔다 (색만으로 구분하지 않는다, 문구 필수).
- 탭은 `role="tablist"`, 각 버튼은 `role="tab"`과 `aria-selected`.
- 키보드: Tab 순서 = 탭 -> 아이디 -> 비밀번호 -> (확인) -> 보기 토글 -> 제출. 토글은 비밀번호 필드 바로 뒤에 둔다.
- 입력 글자 16px 이상 (iOS 확대 방지). 터치 목표 44px 이상.
- 한글 IME 조합 중 Enter는 제출하지 않는다 (`isComposing` 확인).
- 배경 캔버스는 `aria-hidden="true"`이고 포커스를 받지 않는다.

## 8. 세션과 저장 (v1과 같음)

- 아이디와 비밀번호는 브라우저에 저장하지 않는다 (화면에 "기억하기" 항목 없음).
- 로그인 세션은 Supabase Auth가 관리한다. 새로고침 후 세션이 살아 있으면 이 화면을 건너뛴다.

## 9. 360px 체크 항목 (QA)

- [ ] 가로 스크롤 없음. 패널 가로 328px, 패널 좌우 16px.
- [ ] 배경 맵이 화면 전체를 덮고, 아래쪽에 잔디와 흙이 보인다 (빈 단색 영역 없음).
- [ ] LOCAL MODE 칩이 패널 안 맨 아래에 있고, 스크롤해도 다른 요소와 겹치지 않는다.
- [ ] 회원가입 모드에서 세로 스크롤 시 패널만 움직이고 배경은 고정.
- [ ] 스킨 테두리가 흐리지 않다 (픽셀이 선명한 정사각형).
