# 화면 설계: 로그인 / 회원가입

참조: `docs/design/style-guide.md` (색, 폰트, 간격). 인증은 ARCHITECTURE 3번 결정을 따른다 (아이디 -> `<아이디>@mushroom.local` 매핑은 화면에 드러내지 않는다).

## 1. 목적과 진입

- 앱 첫 화면. 세션이 있으면 건너뛴다 (로그인 상태이면 2단계 판정으로 이동).
- 로그인 성공 후 분기:
  - 캐릭터가 있으면 -> 인게임 (`game.md`)
  - 캐릭터가 없으면 -> 캐릭터 생성 (`character-create.md`)
- 회원가입 성공 후: 항상 캐릭터 생성으로 이동한다 (신규 계정은 캐릭터가 없다).

## 2. 레이아웃

### 2.1 공통

- 전체 화면 배경: `sky-top` -> `sky-bottom` 세로 그라데이션. 화면 하단 96px은 잔디 띠 (`grass-light` 1px 윗줄, `grass` 본체) 장식. 장식 영역은 클릭을 막지 않는다 (`pointer-events: none`).
- 카드: 세로 가운데 정렬, 배경 `panel`, 모서리 `radius-lg` (12px), 그림자 `shadow-panel`, 패딩 24px.

### 2.2 데스크톱 (720px 이상)

- 카드 가로 360px 고정.

### 2.3 모바일 (720px 미만, 최소 360px)

- 카드 가로 = 뷰포트 폭 - 32px (좌우 16px 여백).
- 패딩 20px.
- 카드 상단은 뷰포트 상단에서 48px 떨어진다.
- 가로 스크롤 금지.

### 2.4 카드 내부 순서 (위 -> 아래)

| 순서 | 요소 | 규격 |
|---|---|---|
| 1 | 로고 "버섯마을" | `fs-xl` 28px 굵기 700, `text`, 가운데 정렬 |
| 2 | 부제 "친구들과 함께 노는 작은 마을" | `fs-sm` 14px, `text-muted`, 가운데 정렬. 로고와 4px |
| 3 | 탭 (세그먼트 컨트롤) | 높이 40px, 배경 `panel-alt`, 모서리 `radius-md`. 두 버튼 50%씩. 활성: 배경 `primary`, 글자 `primary-text` 700. 비활성: 투명, 글자 `text-muted`. 부제와 24px 간격 |
| 4 | 오류 배너 (있을 때만) | 배경 `error-bg`, 글자 `error` `fs-sm`, 패딩 8px 12px, 모서리 `radius-md`. `role="alert"`. 탭과 16px 간격 |
| 5 | 아이디 필드 | 라벨 + 입력 + 도움말 + 필드 오류 |
| 6 | 비밀번호 필드 | 라벨 + 입력 + 도움말 + 필드 오류 |
| 7 | 비밀번호 확인 필드 (회원가입만) | 라벨 + 입력 + 필드 오류 |
| 8 | 제출 버튼 | 가로 100%, 높이 48px |

필드 사이 간격 16px.

### 2.5 필드 규격

- 라벨: `fs-sm` 14px 굵기 700, `text`. 입력 위 4px.
- 입력: 높이 44px, 가로 100%, 패딩 0 12px, 테두리 1.5px `border`, 모서리 `radius-md`, 배경 `#FFFFFF`, 글자 `fs-md` 16px `text`. 플레이스홀더 색 `text-muted`.
- 입력 포커스: 테두리 `secondary`, 바깥 3px `focus` 링 (투명도 40%, 즉 `rgba(77,163,255,0.4)`).
- 오류 상태: 테두리 2px `error`, `aria-invalid="true"`.
- 비활성 상태: 배경 `panel-alt`, 글자 `text-disabled`.
- 도움말: `fs-xs` 12px `text-muted`, 입력 아래 4px.
- 필드 오류: `fs-xs` 12px 굵기 700 `error`, 입력 아래 4px. 입력 바로 아래 한 줄. 도움말 자리를 대체한다.
- 비밀번호 "보기" 토글: 입력 오른쪽 안쪽, 44 x 44 영역, 글자 `fs-sm` 14px `secondary-text`. 누르면 `type`을 text/password로 바꾼다. `aria-pressed`로 상태를 알린다. 라벨 "보기" / "숨기기".

## 3. 입력 필드

| 필드 | 모드 | 속성 | 검증 규칙 |
|---|---|---|---|
| 아이디 | 로그인, 회원가입 | `type="text"`, `autocomplete="username"`, `autocapitalize="none"`, `spellcheck="false"`, `maxlength="16"`, `inputmode="latin"` | 정규식 `^[a-z0-9_]{4,16}$`. 대문자 자동 변환 없음 (대문자는 형식 오류) |
| 비밀번호 | 로그인 | `type="password"`, `autocomplete="current-password"`, `maxlength="72"` | 검사 없음 (서버 판단). 빈 값만 막는다: 오류 문구 없이 제출 버튼 비활성 |
| 비밀번호 | 회원가입 | `type="password"`, `autocomplete="new-password"`, `maxlength="72"` | 8자 이상 (문자 수 기준). 공백 포함 여부는 허용 |
| 비밀번호 확인 | 회원가입 | `type="password"`, `autocomplete="new-password"`, `maxlength="72"` | 비밀번호와 완전 일치 |

설계 메모: 비밀번호 확인 필드는 이 화면 요구에 없던 항목이다. 오타로 가입 실패를 줄이기 위해 추가했다. 빼도 화면 구조에 영향은 없다.

### 3.1 검증 시점

- 필드에서 포커스가 떠날 때 (blur): 해당 필드의 형식 검사. 틀리면 필드 오류 표시.
- 제출할 때: 모든 필드를 검사하고 첫 번째 오류 필드로 포커스를 옮긴다.
- 입력 중: 이미 표시된 오류는 값이 규칙을 통과하는 순간 지운다. 새 오류는 blur 또는 제출 때만 띄운다.
- 아이디 중복은 서버 응답으로만 확인한다 (입력 중 중복 확인 호출 없음).

## 4. 오류 문구 (정확히 이 문장을 사용)

| 코드 | 상황 | 표시 위치 | 문구 |
|---|---|---|---|
| `ID_FORMAT` | 아이디 형식 오류 (대문자, 특수문자, 3자 이하, 17자 이상, 한글) | 아이디 필드 아래 | 아이디는 영문 소문자, 숫자, 밑줄(_)을 사용해 4~16자로 입력하세요. |
| `PW_SHORT` | 비밀번호 8자 미만 (회원가입) | 비밀번호 필드 아래 | 비밀번호는 8자 이상 입력하세요. |
| `PW_MISMATCH` | 비밀번호 확인 불일치 (회원가입) | 비밀번호 확인 필드 아래 | 비밀번호가 일치하지 않습니다. |
| `ID_TAKEN` | 아이디 중복 (회원가입 응답) | 아이디 필드 아래 | 이미 사용 중인 아이디입니다. |
| `LOGIN_FAILED` | 로그인 실패 (아이디 없음 또는 비밀번호 틀림) | 상단 오류 배너 | 아이디 또는 비밀번호가 올바르지 않습니다. |
| `NETWORK` | 네트워크 오류 (요청 실패, 시간 초과, 오프라인) | 상단 오류 배너 | 연결에 문제가 있습니다. 인터넷 연결을 확인한 뒤 다시 시도하세요. |
| `SERVER` | 그 밖의 서버 오류 | 상단 오류 배너 | 문제가 발생했습니다. 잠시 후 다시 시도하세요. |

규칙:
- `LOGIN_FAILED`는 아이디가 존재하는지 드러내지 않는다. 문구를 바꾸지 않는다.
- `LOGIN_FAILED` 발생 시 아이디는 유지하고 비밀번호 필드만 비운다. 비운 뒤 비밀번호 필드에 포커스를 준다.
- 배너 오류는 다음 제출 시 지운다. 필드 오류는 해당 값이 바뀌면 지운다.
- `ID_TAKEN`은 회원가입에서만 나온다. 로그인 모드에서 받으면 `LOGIN_FAILED`로 처리한다.

## 5. 상태

| 상태 | 제출 버튼 | 입력 | 탭 | 표시 |
|---|---|---|---|---|
| 기본 | 활성. 라벨 "로그인" 또는 "가입하고 시작하기" | 활성 | 활성 | 없음 |
| 필드 오류 | 활성 | 활성 (오류 필드는 `aria-invalid`) | 활성 | 필드 오류 문구 |
| 처리 중 | 비활성. 스피너 16px + "로그인 중..." 또는 "가입 중..." | 모두 비활성 (`disabled`) | 비활성 | 없음 |
| 배너 오류 | 활성 | 활성 | 활성 | 상단 배너 |
| 완료 | 비활성 | 비활성 | 비활성 | 화면 전환 (페이드 200ms) |

처리 중 세부:
- 스피너: 16 x 16px 원형, 테두리 2px `primary-text`, 한쪽만 투명, 0.8초 회전. 회전이 멈춰도 상태는 유지된다 (`prefers-reduced-motion`이면 회전 대신 깜빡임 없이 정지).
- 제출 중 Enter 연타로 두 번 요청하지 않는다.

버튼 규격:
- 높이 48px, 가로 100%, 모서리 `radius-md`.
- 배경 `primary`, 글자 `primary-text` 16px 굵기 700, 하단 그림자 `shadow-btn`.
- 호버: 배경 `primary-hover`.
- 누름: `translateY(2px)`, 그림자 `shadow-btn-pressed`.
- 비활성: 배경 `panel-alt`, 글자 `text-disabled`, 그림자 없음.
- 포커스: 3px `focus` 링 (바깥).

## 6. 동작

| 동작 | 결과 |
|---|---|
| 탭 "로그인" 또는 "회원가입" 누름 | 모드 전환. 입력한 아이디는 유지. 비밀번호와 확인 값은 비운다. 모든 오류 지움. 확인 필드는 회원가입에서만 보인다 |
| 제출 (버튼 또는 비밀번호 필드에서 Enter) | 검사 -> 통과하면 요청. 실패하면 첫 번째 오류 필드로 포커스 |
| 아이디 필드에서 Enter | 비밀번호 필드로 포커스 이동 (제출하지 않음) |
| 제출 성공 (로그인) | 캐릭터 확인 후 인게임 또는 캐릭터 생성으로 이동 |
| 제출 성공 (회원가입) | 캐릭터 생성으로 이동 |
| 세션 확인 중 (앱 시작 직후) | 카드 자리에 스피너만 표시. 최대 3초. 넘으면 로그인 화면 표시 + `NETWORK` 배너 |

화면 전환은 페이드 200ms. 전환 중 뒤로가기는 로그인 화면으로 돌아오지 않게 한다 (히스토리 교체).

## 7. 접근성과 입력 세부

- 모든 입력에 `<label for>`를 연결한다. 도움말과 오류는 `aria-describedby`로 연결한다.
- 배너 오류는 `role="alert"`. 필드 오류는 입력 바로 아래에 텍스트로 둔다 (색만으로 구분하지 않는다, 문구 필수).
- 탭은 `role="tablist"`, 각 버튼은 `role="tab"`과 `aria-selected`.
- 키보드: Tab 순서 = 탭 -> 아이디 -> 비밀번호 -> (확인) -> 보기 토글 -> 제출. 토글은 비밀번호 필드 바로 뒤에 둔다.
- 입력 글자 16px 이상 (iOS 확대 방지). 터치 목표 44px 이상.
- 한글 IME 조합 중 Enter는 제출하지 않는다 (`isComposing` 확인).

## 8. 세션과 저장

- 아이디와 비밀번호는 브라우저에 저장하지 않는다 (화면에 "기억하기" 항목 없음).
- 로그인 세션은 Supabase Auth가 관리한다. 새로고침 후 세션이 살아 있으면 이 화면을 건너뛴다.
