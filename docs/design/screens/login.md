# 화면 설계: 로그인 / 회원가입

버전: 3.0 (2026-10-14, 사이클 3 블록 UI). 화면 흐름, 입력 규칙, 오류 문구, 상태, 동작, 접근성은 v1/v2와 같다. 바뀐 것: 2장(배경, 로고, 패널, 필드를 블록 CSS 컴포넌트로), 5장(버튼과 로딩 표시), 9장(체크 항목).
참조: `docs/design/style-guide.md` v3 (토큰 3장, 컴포넌트 5장), 구현 CSS `docs/design/ui-kit.css`. 인증은 ARCHITECTURE 3번 결정을 따른다 (아이디 → `<아이디>@mushroom.local` 매핑은 화면에 드러내지 않는다).
시안: `docs/design/ref/c3/login-desktop.png` (1280x800), `docs/design/ref/c3/login-mobile.png` (360x640). 시안은 오류 배너와 비밀번호 포커스 상태를 함께 보여 준다.

## 1. 목적과 진입

- 앱 첫 화면. 세션이 있으면 건너뛴다 (로그인 상태이면 2단계 판정으로 이동).
- 로그인 성공 후 분기:
  - 캐릭터가 있으면 -> 인게임 (`game.md`)
  - 캐릭터가 없으면 -> 캐릭터 생성 (`character-create.md`)
- 회원가입 성공 후: 항상 캐릭터 생성으로 이동한다 (신규 계정은 캐릭터가 없다).

## 2. 레이아웃

DOM 골격 (클래스는 `ui-kit.css`):

```html
<div class="bk-world" aria-hidden="true">
  <div class="bk-clouds"> .bk-cloud x 6 </div>
  <div class="bk-world__hills"></div>
  <div class="bk-world__ground"></div>
</div>
<main class="scr-auth">
  <h1 class="bk-logo"><span class="bk-ico bk-ico--mush" aria-hidden="true"></span>버섯마을</h1>
  <section class="bk-panel card-login"> 부제, 탭, 배너, 필드, 제출, LOCAL MODE 줄 </section>
</main>
```

### 2.1 배경 (`.bk-world`, style-guide 5.11)

| 항목 | 값 |
|---|---|
| 요소 | `position: fixed; inset: 0; z-index: 0; pointer-events: none;` `aria-hidden="true"`. 맵 PNG나 장면 이미지를 흐리게 깔지 않는다 (픽셀 깨짐) |
| 하늘 | `k1` → `k5` 하드 스톱 5단 띠 (style-guide 5.11) |
| 구름 | 블록 구름 6개 (같은 배치 2벌). `left` 4% / 24% / 40% / 54% / 74% / 90%, `top` 76 / 36 / 132 / 76 / 36 / 132px. 24%, 74%는 큰 구름(`.bk-cloud--b`). 묶음이 240초에 한 바퀴 왼쪽으로 흐른다 |
| 언덕 + 잔디 블록 띠 | 화면 아래 96px 잔디/흙 타일 띠, 그 위 48px 민트 블록 언덕 |
| 동작 줄이기 | `prefers-reduced-motion: reduce`이면 구름 정지 |
| 로딩 / 실패 | CSS만이라 로딩 단계가 없다. 타일 SVG를 못 그리면 하늘 띠만 보인다 (조작에 영향 없음) |

캐릭터 생성 화면도 같은 배경을 쓴다. 로그인 → 생성 전환 때 배경 요소는 그대로 둔다.

### 2.2 로고 (패널 위)

- `.bk-logo` (style-guide 5.10): 버섯 도트 아이콘 2배(32 x 28) + 12px + "버섯마을" 40px 900 (모바일 32px).
- 글자 `c1`, `w4` 2px 외곽선 + `r2` / `r3` 블록 두께 + `ink` 바닥선 (`text-shadow`, 블러 0).
- 가운데 정렬, `<h1>`. 패널과 간격 16px.

### 2.3 데스크톱 (720px 이상)

- 로고 + 패널 묶음을 세로 가운데에 둔다. 아래 112px(잔디 띠 96 + 16)는 비워 둔다. 묶음이 뷰포트보다 길면 위 32px부터 시작하고 페이지가 스크롤된다.
- 패널 박스 가로 360px (시각 364px: 계단 테두리 좌우 2px).

### 2.4 모바일 (720px 미만, 최소 360px)

- 위 여백 32px, 로고 32px.
- 패널 박스 가로 = `100vw - 36px` (시각 폭 = 화면 - 32, 좌우 16px). 360 폭에서 박스 324px, 내용 292px.
- 내용이 길면(회원가입 모드) 페이지가 세로로 스크롤된다. 배경은 고정이라 같이 움직이지 않는다. 패널이 잔디 띠와 겹쳐도 된다 (패널이 위).
- 가로 스크롤 금지.

### 2.5 패널 (`.bk-panel.card-login`, style-guide 5.1)

- 크림 바탕 + 흰/크림 베벨 + `w4` 계단 테두리 + 아래 블록 두께. 패딩 16px.
- 내부 순서 (위 -> 아래):

| 순서 | 요소 | 규격 |
|---|---|---|
| 1 | 부제 "친구들과 함께 노는 작은 마을" | `.bk-logo-sub` 14px 700 `w4`, 가운데 |
| 2 | 탭 (세그먼트) | `.bk-tabs` 2칸, 높이 40px, 간격 8px. 활성 = 잔디 블록 눌림(초록, 2px 내려감), 비활성 = 돌 블록(글자 `hb1`, hover 하늘색). 부제와 16px |
| 3 | 오류 배너 (있을 때만) | `.bk-banner--error` (분홍 바탕, `r3` 계단 테두리 + 아래 두께). `role="alert"`. 탭과 16px |
| 4 | 아이디 필드 | `.bk-field`: 라벨 + 입력 + 도움말/오류 |
| 5 | 비밀번호 필드 | 라벨 + 입력(+ "보기" 토글 링크) + 도움말/오류 |
| 6 | 비밀번호 확인 필드 (회원가입만) | 라벨 + 입력 + 오류 |
| 7 | 제출 버튼 | `.bk-btn.bk-btn--primary.bk-btn--block`, 박스 높이 44px, 마지막 필드와 24px |
| 8 | LOCAL MODE 줄 (local 모드만) | `.card-foot`: `.bk-chip--mode` "LOCAL MODE" + 4px + 12px `w3` "이 브라우저에만 저장됩니다". 제출 버튼 아래 16px, 가운데 |

필드 사이 16px.

### 2.6 필드 규격 (style-guide 5.4)

- 라벨: 14px 700 `ink`, 입력 위 4px.
- 입력: 박스 높이 44px, 가로 100%, 흰 바탕 + 오목 베벨 + `w3` 계단 테두리. 글자 16px 400 `ink`, 플레이스홀더 `w3`.
- 포커스: 테두리가 `u3` 2단 + 안쪽 `u1` 링. 별도 outline 없음.
- 오류: `aria-invalid="true"` → `r3` 테두리 + `r1` 안쪽 링. 포커스 중이면 포커스 모양이 우선이고 오류 문구는 계속 보인다.
- 비활성: `c2` 바탕, `c3` 테두리, 글자 `w3`.
- 도움말: 12px 700 `w3`, 입력 아래 4px.
- 필드 오류: 12px 700 `r3`, 입력 아래 4px. 도움말 자리를 대체한다.
- 비밀번호 "보기" 토글: `.bk-link` (토글 링크, style-guide 5.5). 입력 오른쪽 안쪽(`.bk-input-end`), 44 x 44 영역, 14px 700 `u3` 밑줄 2px. 입력에는 `.bk-input--with-end`. 누르면 `type`을 text/password로 바꾸고 `aria-pressed`와 글자("보기" / "숨기기")를 바꾼다.

## 3. 입력 필드 (v1과 같음)

| 필드 | 모드 | 속성 | 검증 규칙 |
|---|---|---|---|
| 아이디 | 로그인, 회원가입 | `type="text"`, `autocomplete="username"`, `autocapitalize="none"`, `spellcheck="false"`, `maxlength="16"`, `inputmode="latin"` | 정규식 `^[a-z0-9_]{4,16}$`. 대문자 자동 변환 없음 (대문자는 형식 오류) |
| 비밀번호 | 로그인 | `type="password"`, `autocomplete="current-password"`, `maxlength="72"` | 검사 없음 (서버 판단). 빈 값만 막는다: 오류 문구 없이 제출 버튼 비활성 |
| 비밀번호 | 회원가입 | `type="password"`, `autocomplete="new-password"`, `maxlength="72"` | 8자 이상 (문자 수 기준). 공백 포함 여부는 허용 |
| 비밀번호 확인 | 회원가입 | `type="password"`, `autocomplete="new-password"`, `maxlength="72"` | 비밀번호와 완전 일치 |

도움말 문구: 아이디 "영문 소문자, 숫자, 밑줄(_) 4~16자", 비밀번호(회원가입) "8자 이상". 로그인 모드 비밀번호에는 도움말이 없다.

### 3.1 검증 시점

- 필드에서 포커스가 떠날 때 (blur): 해당 필드의 형식 검사. 틀리면 필드 오류 표시.
- 제출할 때: 모든 필드를 검사하고 첫 번째 오류 필드로 포커스를 옮긴다.
- 입력 중: 이미 표시된 오류는 값이 규칙을 통과하는 순간 지운다. 새 오류는 blur 또는 제출 때만 띄운다.
- 아이디 중복은 서버 응답으로만 확인한다 (입력 중 중복 확인 호출 없음).

## 4. 오류 문구 (v1과 같음, 정확히 이 문장을 사용)

| 코드 | 상황 | 표시 위치 | 문구 |
|---|---|---|---|
| `ID_FORMAT` | 아이디 형식 오류 (대문자, 특수문자, 3자 이하, 17자 이상, 한글) | 아이디 필드 아래 | 아이디는 영문 소문자, 숫자, 밑줄(_)을 사용해 4~16자로 입력하세요. |
| `PW_SHORT` | 비밀번호 8자 미만 (회원가입) | 비밀번호 필드 아래 | 비밀번호는 8자 이상 입력하세요. |
| `PW_MISMATCH` | 비밀번호 확인 불일치 (회원가입) | 비밀번호 확인 필드 아래 | 비밀번호가 일치하지 않습니다. |
| `ID_TAKEN` | 아이디 중복 (회원가입 응답) | 아이디 필드 아래 | 이미 사용 중인 아이디입니다. |
| `LOGIN_FAILED` | 로그인 실패 (아이디 없음 또는 비밀번호 틀림) | 상단 오류 배너 | 아이디 또는 비밀번호가 올바르지 않습니다. |
| `NETWORK` | 네트워크 오류 (요청 실패, 시간 초과, 오프라인) | 상단 오류 배너 | 연결에 문제가 있습니다. 인터넷 연결을 확인한 뒤 다시 시도하세요. |
| `SERVER` | 그 밖의 서버 오류 | 상단 오류 배너 | 문제가 발생했습니다. 잠시 후 다시 시도하세요. |

규칙:
- `LOGIN_FAILED`는 아이디가 존재하는지 드러내지 않는다. 문구를 바꾸지 않는다.
- `LOGIN_FAILED` 발생 시 아이디는 유지하고 비밀번호 필드만 비운다. 비운 뒤 비밀번호 필드에 포커스를 준다.
- 배너 오류는 다음 제출 시 지운다. 필드 오류는 해당 값이 바뀌면 지운다.
- `ID_TAKEN`은 회원가입에서만 나온다. 로그인 모드에서 받으면 `LOGIN_FAILED`로 처리한다.

## 5. 상태

| 상태 | 제출 버튼 | 입력 | 탭 | 표시 |
|---|---|---|---|---|
| 기본 | 활성. 라벨 "로그인" 또는 "가입하고 시작하기" | 활성 | 활성 | 없음 |
| 필드 오류 | 활성 | 활성 (오류 필드는 `aria-invalid="true"` → 빨간 테두리) | 활성 | 필드 오류 문구 |
| 처리 중 | 비활성 모양. 로딩 점 + "로그인 중" 또는 "가입 중" | 모두 `disabled` (크림 바탕) | 비활성 | 없음 |
| 배너 오류 | 활성 | 활성 | 활성 | 상단 오류 배너 |
| 완료 | 비활성 | 비활성 | 비활성 | 화면 전환 (패널만 페이드 200ms, 배경 유지) |

### 5.1 로딩 점 (`.bk-dots`, style-guide 5.9)

- 4 x 4px 정사각형 3개, 간격 4px, 색 = 버튼 글자색 (비활성 버튼 위에서는 `w3`). 전체 20 x 4px.
- 900ms 주기로 하나씩 불투명 1, 나머지 0.35. 계단식(부드러운 전환 없음).
- `prefers-reduced-motion: reduce`이면 세 점 모두 1로 정지.
- 버튼 안에서 글자 왼쪽 8px. `aria-hidden="true"`, 상태는 버튼 글자가 전달한다.
- 제출 중 Enter 연타로 두 번 요청하지 않는다.

### 5.2 버튼 규격 (style-guide 5.2, primary = 잔디 블록)

- 박스 높이 44px, 가로 100% (시각: 위 2, 좌우 2, 아래 4px 더).
- 기본: 정면 `g2`, 윗면 베벨 `g1`, 옆면 베벨 `g3`, 아래 두께 흙 `w3`, 테두리 `g4`. hover: 정면 `g1`, 윗면 `white`.
- 누름: 2px 아래로 + 베벨 반전 + 두께 사라짐 (아래 끝 위치는 그대로).
- 비활성: 크림 `c2` 정면 + `c3` 테두리, 글자 `w3`, 눌리지 않음.
- 글자 16px 700 `ink`.
- 포커스: `outline: 2px solid var(--focus); outline-offset: 4px`.

## 6. 동작 (v1과 같음)

| 동작 | 결과 |
|---|---|
| 탭 "로그인" 또는 "회원가입" 누름 | 모드 전환. 입력한 아이디는 유지. 비밀번호와 확인 값은 비운다. 모든 오류 지움. 확인 필드는 회원가입에서만 보인다 |
| 제출 (버튼 또는 비밀번호 필드에서 Enter) | 검사 -> 통과하면 요청. 실패하면 첫 번째 오류 필드로 포커스 |
| 아이디 필드에서 Enter | 비밀번호 필드로 포커스 이동 (제출하지 않음) |
| 제출 성공 (로그인) | 캐릭터 확인 후 인게임 또는 캐릭터 생성으로 이동 |
| 제출 성공 (회원가입) | 캐릭터 생성으로 이동 |
| 세션 확인 중 (앱 시작 직후) | 패널 자리에 `.bk-panel`(가로 동일, 높이 96px) + 가운데 로딩 점(`ink`)만 표시. 최대 3초. 넘으면 로그인 화면 표시 + `NETWORK` 배너 |

화면 전환은 페이드 200ms. 전환 중 뒤로가기는 로그인 화면으로 돌아오지 않게 한다 (히스토리 교체).

## 7. 접근성과 입력 세부 (v1과 같음)

- 모든 입력에 `<label for>`를 연결한다. 도움말과 오류는 `aria-describedby`로 연결한다.
- 배너 오류는 `role="alert"`. 필드 오류는 입력 바로 아래에 텍스트로 둔다 (색만으로 구분하지 않는다, 문구 필수).
- 탭은 `role="tablist"`, 각 버튼은 `role="tab"`과 `aria-selected`.
- 키보드: Tab 순서 = 탭 -> 아이디 -> 비밀번호 -> (확인) -> 보기 토글 -> 제출. 토글은 비밀번호 필드 바로 뒤에 둔다.
- 입력 글자 16px 이상 (iOS 확대 방지). 터치 목표 44px 이상.
- 한글 IME 조합 중 Enter는 제출하지 않는다 (`isComposing` 확인).
- 배경 `.bk-world`는 `aria-hidden="true"`이고 포커스를 받지 않는다.

## 8. 세션과 저장 (v1과 같음)

- 아이디와 비밀번호는 브라우저에 저장하지 않는다 (화면에 "기억하기" 항목 없음).
- 로그인 세션은 Supabase Auth가 관리한다. 새로고침 후 세션이 살아 있으면 이 화면을 건너뛴다.
