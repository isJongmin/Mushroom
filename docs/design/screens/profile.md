# 화면 설계: 프로필 (닉네임 + 캐릭터 꾸미기)

버전: 4.0 (2026-10-15, 사이클 4 신규). `character-create.md` v3을 기반으로 다시 썼다(그 문서는 폐기).
바뀐 것: 로그인/계정 없음, 서버 통신 없음, 닉네임은 형식만 검사(중복 검사 없음 — 방 입장 때 서버가 검사), 버튼이 "입장하기"(최초) / "취소" + "저장"(로비에서 수정), 저장 위치는 localStorage. 꾸미기 UI(탭, 슬롯, 프리셋, 회전 미리보기)는 v3 그대로.
참조: ARCHITECTURE 결정 3(익명 로그인, `mushroom:profile`, 닉네임 정규식), "화면 흐름 (사이클 4)". style-guide v4 (5.12 슬롯, 5.13 프리셋, 5.14 미리보기, 11장 v4 컴포넌트). 구현 CSS `docs/design/ui-kit.css`.
시안: `docs/design/ref/c4/profile-first-desktop.png` (최초, 1280 폭 전체 길이), `profile-desktop.png` (수정 모드 1280x800), `profile-mobile.png` (최초 360x640), `profile-mobile-full.png` (최초 360 전체 길이).

## 1. 목적과 진입

| 모드 | 진입 조건 | 제목 | 버튼 | 완료 후 |
|---|---|---|---|---|
| 최초 (`first`) | localStorage `mushroom:profile`이 없거나 읽을 수 없음(JSON 오류, 닉네임 형식 불일치) | "프로필 만들기" | "입장하기" (primary, 1개) | 로비 |
| 수정 (`edit`) | 로비의 "꾸미기" 버튼 | "프로필 수정" | "취소" (secondary) + "저장" (primary) | 로비 |

- 이 화면은 서버와 통신하지 않는다. 앱 시작 시 익명 로그인(`init()`)은 이 화면과 별개로 진행되고, 이 화면은 그 결과를 기다리지 않는다(로비가 기다린다).
- 프로필이 저장돼 있으면 앱은 로비부터 시작한다(ARCHITECTURE 화면 흐름). 단 sessionStorage `mushroom:room`이 있으면 방 재입장을 먼저 시도한다(`room.md` 1장).
- 방 안에서는 프로필을 바꿀 수 없다(로비에서만). 바꾼 닉네임/외형은 다음 방 입장부터 적용된다.

## 2. 레이아웃

v3 `character-create.md` 2장과 같다. 다른 점만 적는다.

### 2.1 공통

- 배경 `.bk-world` (style-guide 5.11). 프로필 ↔ 로비 전환 때 유지한다(다시 만들지 않음). 방에 들어갈 때 제거.
- 최초 모드만 카드 위에 작은 로고 `.bk-logo.bk-logo--sm` (`<h1>`, 글자 24px, 모바일 20px, 버섯 아이콘 32x28) → 16px → 카드. 카드 왼쪽 끝에 맞춘다. 수정 모드는 로고 없음(로비에서 넘어온 맥락).
- 카드 `.bk-panel.card-create`. 맨 위 줄 `.card-head`: 제목 `<h2 class="card-title">` 20px 700. 오른쪽 버튼 없음(v3의 "로그아웃" 삭제).
- 본문 `.create-grid` 네 영역 prev / parts / nick / cta, DOM 순서 같음.
- LOCAL MODE 줄(local 모드만) `.card-foot`: 모드 칩 + "프로필은 이 브라우저에만 저장돼요" 12px `w3`. (supabase 모드에서도 프로필은 브라우저에만 있지만, 안내는 local 모드에서만 보인다 — 아래 6장 안내 문구는 모드와 무관하게 항상 표시.)

### 2.2 데스크톱 (720px 이상)

- 카드 박스 800px, 왼쪽 열 240 / 오른쪽 504 (v3 그대로).
- 왼쪽 열 아래: `nick` → 16px → `cta`.
  - 최초: "입장하기" `.bk-btn--primary.bk-btn--block` 240 x 44.
  - 수정: `.cta-pair` 2칸 그리드(각 114, 간격 12): 왼쪽 "취소" secondary, 오른쪽 "저장" primary.
- 높이: 수정 모드 카드는 1280x800에서 한 화면에 들어간다. 최초 모드는 로고(40 + 16)만큼 길어져 800px 높이에서 약 38px 세로 스크롤이 생긴다. "입장하기" 버튼은 첫 화면 안(y 약 668)에 있으므로 수용한다. `.scr-auth`는 내용이 화면보다 길면 위에서부터 배치(v3 규칙).

### 2.3 모바일 (720px 미만)

- v3 2.3과 같은 한 열 순서: 제목 → 미리보기 + 방향 버튼 → 프리셋 → 탭 → 슬롯 → 닉네임 → cta(sticky) → LOCAL MODE 줄.
- 최초 모드는 맨 위에 로고(20px) → 12px → 카드.
- cta는 `position: sticky; bottom: 0` + `c1` 띠(v3 `.create-cta`). 수정 모드는 띠 안에 `.cta-pair`(각 칸 `(300 - 12) / 2 = 144`px).

## 3. 미리보기, 4. 파츠 선택

v3 `character-create.md` 3장, 5장과 같다(회전 미리보기 앞/옆/뒤 + 걷기, 카테고리 탭 7개, 슬롯 그리드, 프리셋 6종, 현재 값 줄, 매니페스트 실패 배너). 그 문서가 폐기 표시돼도 3장과 5장 규격은 이 문서의 일부로 유효하다.

초기값:
- 최초: 7개 키 모두 manifest 각 파츠 첫 항목(모자 `none`). 활성 탭 = 머리.
- 수정: 저장된 `avatar` 값. manifest에 없는 id는 해당 파츠 기본값으로 바꿔 보여 주고, 저장하면 그 값으로 고쳐 저장한다.

## 5. 닉네임 입력

### 5.1 필드

| 항목 | 값 |
|---|---|
| 라벨 | "닉네임" (14px 700) |
| 입력 | `.bk-input.bk-input--with-end`, 박스 높이 44, 16px 400, `maxlength="12"`, `autocomplete="off"`, `autocapitalize="off"`, `spellcheck="false"`, `enterkeyhint="done"` |
| 글자 수 | `.bk-counter` "N/12", 입력 오른쪽 안. 비어 있으면 숨김 |
| 정규식 | `^[가-힣A-Za-z0-9]{2,12}$` (ARCHITECTURE 결정 3). 앞뒤 공백은 제거하고 검사 |
| 초기값 | 최초: 빈 값. 수정: 저장된 닉네임 |

중복 검사는 하지 않는다. 같은 방의 활성 멤버 사이에서만 중복이 금지되고 서버가 입장할 때 검사한다(`lobby.md` 6장 NICK_TAKEN).

### 5.2 상태 줄 (필드 아래 4px, 높이 20px 고정, 12px 700, `aria-live="polite"`)

| 상태 | 조건 | 색 | 문구 | 아이콘 | 입력 모양 |
|---|---|---|---|---|---|
| 안내 | 빈 값, 아직 입력 안 함 | `w3` | 2~12자, 한글·영문·숫자만 쓸 수 있어요. | 없음 | 기본 |
| 형식 맞음 | 정규식 일치 | `g4` | 쓸 수 있는 형식이에요. | `.bk-ico--check` | 기본 |
| 형식 오류 (`NICK_FORMAT`) | 정규식 불일치 (1자, 13자 이상 붙여넣기, 공백, 특수문자, 이모지, 낱자 자모) | `r3` | 2~12자의 한글, 영문, 숫자만 쓸 수 있어요. | 없음 | `aria-invalid="true"` |

검사 시점 (실시간):
- `input` 이벤트마다 검사한다. 단 한글 조합 중(`compositionstart` ~ `compositionend`)에는 검사하지 않고 직전 상태를 유지한다(조합 중 낱자가 오류로 깜빡이지 않게). `compositionend`에서 검사.
- 처음 입력하는 동안 1자일 때는 오류 대신 "안내" 상태로 둔다. 오류는 (a) 2자 이상인데 불일치, 또는 (b) 필드를 떠날 때(blur) 불일치, 또는 (c) 버튼을 눌렀을 때 불일치이면 보인다. 한 번 오류를 보인 뒤에는 매 입력마다 즉시 갱신한다.

## 6. 버튼과 저장

| 버튼 | 활성 조건 | 동작 |
|---|---|---|
| 입장하기 (최초) | 닉네임 형식 맞음 + manifest 로딩 성공 | 저장 → 로비로 (페이드 200ms, 배경 유지) |
| 저장 (수정) | 같음 | 저장 → 로비로 |
| 취소 (수정) | 항상 | 바꾼 내용을 버리고 로비로. 확인 창 없음(되돌릴 데이터가 서버에 없고 다시 꾸미면 됨) |

- 비활성 모양: 크림 비활성(style-guide 5.2). 비활성 버튼을 눌렀을 때 형식 오류면 상태 줄에 오류를 띄우고 닉네임 필드로 포커스.
- Enter: 닉네임 필드에서 Enter = 주 버튼(입장하기/저장). Esc: 수정 모드에서 "취소"와 같다(입력 중 IME 조합이면 무시).
- 저장 내용: localStorage `mushroom:profile` = `{ "nickname": "<trim 값>", "avatar": { skin, face, hair, hat, top, bottom, shoes } }` (ARCHITECTURE 결정 3, 7개 키).
- 처리 중 상태 없음(동기 저장). 버튼을 누르면 바로 전환.

### 6.1 저장 실패 (`STORAGE`, 클라이언트 전용 코드)

localStorage 쓰기가 예외를 던지면(사생활 보호 모드, 저장 공간 가득 참):
- 프로필은 메모리에만 두고 그대로 로비로 이동한다(사용을 막지 않음).
- 로비 첫 표시 때 정보 배너 `.bk-banner`(오류 아님) 1회: "프로필을 이 브라우저에 저장하지 못했어요. 새로고침하면 다시 만들어야 해요." 다음 로비 동작 때 사라진다.

### 6.2 상시 안내

`nick` 필드 도움말 아래가 아니라 카드 맨 아래 `.card-foot` 자리(LOCAL MODE 칩이 있으면 그 옆)에 12px `w3`: "프로필은 이 브라우저에만 저장돼요". supabase 모드에서도 이 문구를 보인다(칩만 빠짐).

## 7. 오류 문구 (이 화면)

| 코드 | 상황 | 위치 | 문구 |
|---|---|---|---|
| `NICK_FORMAT` | 닉네임 형식 오류 | 닉네임 상태 줄 | 2~12자의 한글, 영문, 숫자만 쓸 수 있어요. |
| `MANIFEST` | 파츠 매니페스트 로딩 실패 | 파츠 영역 오류 배너 `.bk-banner--error` (`role="alert"`) | 파츠 정보를 불러오지 못했어요. 새로고침해 주세요. |
| `STORAGE` | localStorage 쓰기 실패 | 로비 정보 배너 (6.1) | 프로필을 이 브라우저에 저장하지 못했어요. 새로고침하면 다시 만들어야 해요. |

v3의 `NICK_TAKEN`, `NICK_CHECK_FAILED`, `NETWORK`, `SERVER`(생성 요청)는 이 화면에서 없어졌다.
문구 톤: 사이클 4부터 새 화면 문구는 해요체(style-guide 11.1).

## 8. 접근성

- v3 9장과 같다(탭 `tablist`, 슬롯 `radiogroup`, 방향 `radiogroup`, 걷기 `aria-pressed`, 미리보기 `aria-hidden`).
- 닉네임 `<label for>`, 상태 줄 `aria-describedby` + `aria-live="polite"`.
- Tab 순서: 방향 → 걷기 → 프리셋 → 카테고리 탭 → 슬롯 → 닉네임 → (취소) → 입장하기/저장.
- 화면 진입 시 포커스: 최초 = 닉네임 필드가 아니라 제목(`tabindex="-1"`)에 둔다(모바일에서 키보드가 바로 올라와 미리보기를 가리지 않게). 수정 = 제목.

## 9. 360px 체크 항목 (QA)

- [ ] 가로 스크롤 없음. 최초 모드에서 로고 + 카드가 보이고 sticky "입장하기"가 화면 아래에 있다.
- [ ] 수정 모드에서 sticky 띠 안에 "취소" / "저장"이 한 줄 두 칸(각 144px)으로 보인다.
- [ ] 한글 "버섯이"를 조합하는 동안 상태 줄이 오류로 깜빡이지 않는다.
- [ ] "버" 1자 상태에서 blur → 형식 오류 문구, 빨간 테두리.
- [ ] 저장 후 로비의 미니 썸네일/닉네임이 바뀐 값으로 보인다. 새로고침해도 유지된다.
- [ ] 사생활 보호 창(저장 실패)에서도 로비로 넘어가고 정보 배너가 1회 보인다.
