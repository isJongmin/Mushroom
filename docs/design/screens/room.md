# 화면 설계: 방 (맵 + HUD + 채팅 로그)

버전: 4.0 (2026-10-15, 사이클 4). `game.md` v3을 개정한 문서다(그 문서는 폐기).
바뀐 것: 맵이 "방" 단위가 됨(방 이름, 인원 n/20, 나가기), 채팅 로그 패널 추가(입장 시 최근 50개 + 실시간 + 시스템 메시지), 로그아웃 삭제, 채팅 전송이 서버 RPC로, 모바일 HUD 2줄.
그대로인 것: 캔버스 배율/카메라/그리기 순서(style-guide 6장), 닉네임 라벨(7장), 말풍선 규격과 기준선(8장), 이동 조작, 터치 버튼, 채팅 입력 행, 재연결 규칙, 모바일 조작 영역 132px.
참조: ARCHITECTURE 결정 4~6(채팅방 정책, 비공개 채널, 어댑터, 오류 코드), "화면 흐름 (사이클 4)". style-guide v4 11장, `ui-kit.css` 22~23절.
시안 (`docs/design/ref/c4/`): `room-desktop.png` (1280x800, 로그 펼침), `room-desktop-collapsed.png` (로그 접힘 + 읽지 않은 2 + 재연결 실패 배너), `room-mobile.png` (360x640, 로그 접힘 기본), `room-mobile-log.png` (로그 펼침 + "새 메시지 2개" 버튼). 맵은 최종 에셋으로 합성한 정지 화면(아트 640x270, camX 180 / 모바일 180x254, camX 410).

## 1. 진입과 나가기

### 1.1 진입 경로

| 경로 | 처리 |
|---|---|
| 로비에서 입장/만들기 성공 | 이미 멤버 행이 있다. 바로 3단계(채널 연결 + 기록 불러오기) |
| 새로고침 (sessionStorage `mushroom:room` = `{ roomId, nickname }` 있음) | 프로필 확인 → `init()` → 같은 방 재입장 시도(비밀번호 재입력 없이 멤버 행으로 확인, ARCHITECTURE 화면 흐름). 실패하면 sessionStorage를 지우고 로비 + 로비 배너 "방에 다시 들어가지 못했어요. 목록에서 다시 골라 주세요." |

입장 순서: 에셋(맵/아바타 매니페스트) 로딩 + `connectRoom(roomId, handlers, self)` + `recentMessages(roomId)`를 동시에 시작한다. 캔버스는 에셋과 채널이 준비되면 그린다. 기록은 따로 도착하는 대로 로그에 넣는다(캔버스를 막지 않음).

### 1.2 나가기

- 버튼: HUD 오른쪽 위 "나가기" `.bk-btn--sm`(왼쪽 화살표 도트 아이콘 + 글자). **확인 창 없이** 바로 나간다.
  - 판단: 나가도 잃는 것이 없다(대화 기록은 서버에 50개 남고, 방은 비어도 30분 유지, 다시 들어오면 기록을 다시 불러온다). 잠금 방은 다시 들어올 때 비밀번호를 다시 넣어야 하지만, 실수 비용이 확인 창을 매번 거치는 비용보다 작다. 버튼은 화면 모서리에 작게 있고 단축키를 두지 않아 실수로 누르기 어렵다.
  - 쓰던 채팅 입력 내용은 버린다.
- 동작: 버튼 비활성 + 로딩 점 + "나가는 중" → `leave()`(채널) + `leaveRoom(roomId)` (최대 1.5초 기다림, 실패해도 진행 — 하트비트가 멈추면 60초 뒤 서버가 비활성 처리) → sessionStorage `mushroom:room` 삭제 → 로비(페이드 200ms, `.bk-world` 새로 만듦). 로비는 즉시 목록을 갱신한다.
- 탭 닫기/다른 페이지 이동(`pagehide`): `leaveRoom`을 최선으로 1회 보낸다(기다리지 않음). sessionStorage는 지우지 않는다(새로고침 재입장 위해).

## 2. 구성

| 영역 | 내용 | 구현 |
|---|---|---|
| 게임 캔버스 | 맵, 발 그림자, 아바타, 닉네임 라벨, 말풍선 | Canvas 2D (style-guide 6~8장, v3과 같음) |
| HUD | 방 이름(+자물쇠), 접속 인원 n/20, LOCAL MODE 칩, 조작 힌트(데스크톱), 나가기, 상태 배너, (모바일) 채팅 기록 토글 | DOM, `.game-stage`(캔버스와 같은 크기, `position: relative`) 안 `.hud` |

## 3. 데스크톱 레이아웃 (720px 이상)

세로 묶음 [캔버스 → 12px → 채팅 입력 행 → 16px]을 가운데에(v3). 캔버스 크기는 style-guide 6.1(1280x800 → 1280 x 540).

### 3.1 HUD (캔버스 위, 여백 12px)

| 요소 | 위치 | 규격 |
|---|---|---|
| 방 이름 칩 `.bk-chip.hud-room` | 왼쪽 위 | 잠금 방: 자물쇠 도트 아이콘(14x16) + 8 + 이름. 14px 700 `ink`. 최대 가로 360, 넘치면 말줄임. 숨김 글자 "비밀번호 방"(잠금 방만). `title` = 전체 이름 |
| 접속 인원 칩 `.bk-chip.bk-count` | 방 이름 오른쪽 8 | 사람 도트 아이콘 + "N/20명". N = Presence 인원(나 포함). 20 이상이면 `.is-full`. 연결 끊김 중 끝에 `.bk-dot-off`. `aria-label` "접속 인원 N명, 최대 20명" |
| LOCAL MODE 칩 | 인원 칩 오른쪽 8 | local 모드만 |
| 조작 힌트 `.bk-chip--hint` | 오른쪽 위, 나가기 왼쪽 8 | v3 문구 그대로. 캔버스 가로 900 미만이면 숨김 |
| 나가기 `.bk-btn--sm` | 오른쪽 위 | 왼쪽 화살표 + "나가기" (1.2) |
| 상태 배너 `.hud-banner` | 위 가운데, 위에서 52 | 7장. 캔버스 가로 720~1039이고 로그가 펼쳐져 있으면 로그 오른쪽 영역의 가운데(`left = 344 + (W - 356)/2`, 최대 폭 `W - 368`)로 옮긴다(`.game-stage.log-open`) |

### 3.2 채팅 로그 패널 위치와 크기 (결정)

| 항목 | 값 |
|---|---|
| 위치 | 캔버스 **왼쪽 위, HUD 첫 줄 아래**: `left 12, top 56` |
| 가로 | 320px (`--log-w`) |
| 세로 (펼침) | `clamp(120px, 캔버스 세로 - 328px, 240px)`. 1280x800(캔버스 540) → **212px**(메시지 약 9줄), P=3 큰 화면(810) → 240 |
| 세로 (접힘) | 머리줄 32px만 |

판단(왼쪽 아래가 아니라 왼쪽 위로 둔 이유):
- 캔버스 아래쪽은 아바타(발 위 120px), 닉네임 라벨(발 아래 28px), 말풍선이 모이는 곳이다. 아래에 두면 왼쪽 사람들과 말풍선을 덮는다. 위쪽은 하늘과 구름뿐이라 가려도 잃는 정보가 없다.
- 세로 공식은 4줄 말풍선의 위 끝(캔버스 아래에서 `60 + 52*2 + 4 + 8 + 86 = 262px`)보다 8px 위에서 패널이 끝나게 한 것이다: `56 + h <= H - 262 - 8 - 2` → `h = H - 328`. 그래서 데스크톱(P=2)에서는 말풍선과 아바타를 절대 가리지 않는다.
- HUD 첫 줄(방 이름, 인원) 바로 아래라 "이 방의 정보" 묶음으로 읽힌다. 패널 머리줄은 HUD 칩과 같은 블록 언어(테두리 2px, 위 베벨)를 쓴다.
- 채팅 입력(캔버스 아래)과 떨어져 있지만, 실시간 대화는 말풍선으로 보고 로그는 지난 대화를 확인하는 용도라 수용한다.

### 5.2 메시지 종류

| 종류 | 클래스 | 모양 | 예 |
|---|---|---|---|
| 일반 | `.bk-msg` | 닉네임 14px 700 `k3` + 6 + 본문 14px/20 400 `white` + 6 + 시각 11px 700 `st1`. 한 줄에 이어 쓰고 넘치면 줄바꿈(`word-break: keep-all; overflow-wrap: anywhere`) | **밤톨** 안녕하세요~ 12:01 |
| 내 메시지 | `.bk-msg.bk-msg--self` | 왼쪽 2px `y2` 막대 + 왼쪽 패딩 8, 닉네임 `y2`(게임 안 내 라벨과 같은 노랑). 숨김 글자 "나:"를 닉네임 앞에 | **버섯이** 안녕! 나도 왔어 ㅎㅎ 12:04 |

시각 형식: `created_at`을 지역 시각 24시간 "HH:MM". 오늘이 아니면 "M월 D일 HH:MM". `<time datetime="…">`.
다른 사람 닉네임을 사람마다 다른 색으로 칠하지 않는다(팔레트 대비 보장이 어렵고, 닉네임 글자로 구분됨).
모든 글자는 `textContent`로 넣는다.

### 5.3 내용 규칙

1. 입장: `recentMessages(roomId)`(오래된 것부터, 최대 50) 도착 → 1개 이상이면 맨 위에 "이전 대화 N개" 구분 줄 + 메시지들. 0개면 구분 줄 없음.
2. 그 아래 내 입장 시스템 메시지 "<내 닉네임>님이 들어왔어요".
3. 기록 로딩 중: 목록 자리에 `.bk-log__state` 로딩 점 + "대화를 불러오는 중이에요"(`st1`). 실패: 시스템 오류 "이전 대화를 불러오지 못했어요." (재시도 없음, 실시간 메시지는 계속 받음).
4. 실시간 `chat`(서버 송신): 아래에 추가. `id`로 중복 제거(기록과 실시간이 겹치는 순간, 재연결 후 다시 불러올 때).
5. 내 메시지: 서버가 보낸 `chat`(`user_id` = 나)이 도착하면 추가한다(로그는 서버 기준). 말풍선은 v3처럼 보내는 즉시 띄운다.
6. 입장/퇴장 시스템 메시지: Presence `join` → "<닉네임>님이 들어왔어요", `leave` → "<닉네임>님이 나갔어요". 첫 `sync`에 이미 있던 사람은 메시지를 만들지 않는다. 같은 사람이 3초 안에 나갔다 들어오면(재연결 깜빡임) 두 메시지 모두 만들지 않는다(퇴장 메시지를 3초 미뤘다가 그 사이 재입장하면 버림).
7. 연결: 끊김 → 시스템 오류 "연결이 끊어졌어요", 재연결 성공 → 시스템 "다시 연결됐어요". 재연결 뒤 `recentMessages`를 한 번 더 불러와 빠진 메시지를 `id` 순서대로 끼워 넣는다.
8. DOM에는 최근 200개까지만 두고 오래된 것부터 지운다(구분 줄 포함).

### 5.4 자동 스크롤과 "새 메시지"

- "바닥에 붙음" = `scrollHeight - scrollTop - clientHeight <= 24`.
- 새 항목이 추가될 때 바닥에 붙어 있었으면 맨 아래로 즉시 스크롤한다(부드러운 스크롤 없음).
- 사용자가 위로 올려 읽는 중이면 위치를 유지하고, 목록 아래 가운데에 `.bk-log__new` 버튼(primary `.bk-btn--xs`, "새 메시지 N개" + 아래 화살표 도트)을 띄운다. N = 그 뒤로 쌓인 일반/내 메시지 수(시스템 제외), 99 넘으면 "99+".
- 버튼을 누르거나 사용자가 직접 바닥까지 내리면 버튼을 숨기고 N을 0으로.
- 내가 메시지를 보내 내 `chat`이 도착하면 위치와 상관없이 맨 아래로 간다.
- 기록을 처음 불러온 직후에는 맨 아래로.

| 기본 | 펼침 | 접힘(숨김) |
| 기억 | sessionStorage `mushroom:logOpen` (`"1"`/`"0"`)로 탭 안에서 유지 | 기억하지 않음(입장할 때마다 접힘) |
| 접힘 모양 | 머리줄(320 x 32)만 남고 목록 숨김. 제목 오른쪽에 읽지 않은 수 배지 | 패널 숨김, 2줄 토글 버튼에 배지 |
| 버튼 | "접기" ↔ "펼치기" (`aria-expanded`) | 토글 "채팅 기록" / 패널 안 "닫기" |
| 읽지 않은 수 | 접힌 뒤 도착한 일반/내 메시지 수, 99 넘으면 "99+", 0이면 배지 숨김. 펼치면 0 + 맨 아래로 | 같음 |

### 5.6 접근성

- 목록 `<ol role="log" aria-live="polite" aria-relevant="additions" aria-labelledby="(제목 id)">`. 스크린 리더 사용자에게는 이 로그가 대화를 듣는 길이다(말풍선은 캔버스). 기록 50개를 처음 넣을 때는 `aria-busy="true"`로 감쌌다가 끝나면 false(한꺼번에 읽히지 않게).
- 접힘/숨김 중에는 `aria-live`가 읽지 않도록 목록에 `hidden`(모바일) 또는 `display: none`(데스크톱 접힘)을 쓴다.
- 대비(가장 밝은 배경 위 합성색 `#474455` 기준): 본문 `white` 9.4, 닉네임 `k3` 6.4, 내 닉네임 `y2` 6.0, 시스템 `m1` 7.5, 오류 `p1` 6.5, 시각/구분 `st1` 5.5. 모두 4.5:1 이상.
- 패널은 Tab 순서에서 HUD 다음, 채팅 입력 앞. 목록 자체는 `tabindex="0"`(키보드로 스크롤 가능), 포커스 링은 안쪽(-4px).
