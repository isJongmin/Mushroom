# Continuous chat

- Previous input rejected sends during both a one-second cooldown and an outstanding RPC. Acknowledgement latency was also the first time a sender saw their message.
- The composer now accepts up to eight outstanding messages in FIFO order and immediately displays a local pending row. Only the active message is sent; the next request waits 1050 ms after confirmation to respect the existing server limit.
- A matching self realtime event reconciles the active pending row. The RPC response shares the same confirmation path; duplicate IDs are ignored.
- Only explicit RATE_LIMITED rejections retry automatically (at most twice). Other failures retain their text, pause the queue, and expose explicit retry/discard controls. Network errors display acknowledgement uncertainty because the server may already have committed the message.
- Clicking send restores composer focus; IME composition and repeated Enter are guarded. Chat has a direct shortcut next to the bag and opens the log without moving focus. Mobile close returns to gameplay.
- Log scroll writes are coalesced into one animation frame. Unchanged canvas backing sizes are no longer reset on every layout call. Queue timers and late callbacks are disposed when leaving a room.

Validation: `node tests/chat-outbox.test.mjs` exercises slow responses, FIFO ordering, pacing, realtime-before-RPC, explicit rate retry limits, failure preservation, offline resume, queue bounds, discard and cleanup. All 41 JavaScript test files passed. Real remote latency is not eliminated; typing is decoupled from that latency and delivery remains visibly pending until confirmed. Room exit discards unsent local entries.
