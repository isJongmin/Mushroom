# art -> main/front: 사이클 10 맵 (Canva 원본 그림 배경)

날짜: 2026-10-28 / 담당: 아트(맵)
상태: **미리보기 단계, 설치 전**. `assets/map/`은 건드리지 않았다(사이클 9 맵 그대로). 메인이 지시하면 `--install`로 설치한다.

방향 변경 경위: 처음에는 복셀 맵을 다시 만들기로 했다. 진행 중에 메인 지시로 **사용자가 준 Canva 원본 그림을 그대로 배경으로 쓰는 방식**으로 바꿨다. 복셀 재구축은 중단했다. `assets/_src/voxel_map/`은 HEAD(WIP 커밋) 상태 그대로 두었고, 미완성이라 실행되지 않는다. 이번 납품에는 쓰지 않는다. `assets/_src/art2d_map/`도 손대지 않았다.

## 1. 빌드 / 검사 / 미리보기

```
python3 assets/_src/map_canva/build.py --out DIR      # DIR에 sky.png, ground.webp, manifest.json
python3 assets/_src/map_canva/build.py --install      # assets/map/에 쓰고 옛 clouds/far/mid.webp를 지운다 (지시 후)
python3 assets/_src/map_canva/check.py [MAPDIR] [--determinism]
python3 assets/_src/map_canva/preview.py MAPDIR OUTDIR [--k 1.0]
```

- 원본 `assets/_src/map_canva/`: `panels.py`(패널 표: 파일, 지면 행, 발판, 스폰. 원본 px 기준, 정본), `build.py`, `check.py`, `preview.py`, `orig/center.png`(사용자 첨부 1776x896, md5 d795826d…).
- 패널 수는 바꿔도 된다. `orig/left.png`, `orig/right.png`가 생기면 `panels.py`에 `ground`(지면 행), `platforms`, `spawns`를 적기만 하면 된다. 파일이 없거나 `ground`가 None인 패널은 건너뛴다.
- 처리 순서
  1. 원본을 1.25배로 키운다(LANCZOS).
  2. 패널마다 지면 행을 같은 높이로 맞춘다(아래가 모자라면 흙 단면을 거울로 잇는다).
  3. 이음매는 120px(원본) 겹침에서 색 차이가 가장 작은 세로 경로를 찾아 섞는다. 섞는 폭은 하늘과 원경처럼 차이가 작은 행에서 넓고(최대 겹침의 45%), 소품과 지면에서 좁다(6px). 오른쪽 패널 색은 겹친 구간 평균에 맞춘다.
  4. 맵 양 끝 90px은 살짝 흐리고 옅게 마감한다.
  5. 그림 위에 하늘 212px을 덧붙인다(그림 윗줄 색 → 위쪽 더스티 블루 그라데이션, 디더).
- 결정적이다. `--determinism`에서 md5 2회가 같았다.
- 검사 결과: OK. 이음매 처리는 패널이 하나라 아직 실제로 검증하지 못했다. 좌우 패널이 오면 확인한다.

## 2. 실제 값 (중앙 패널만)

| 항목 | 값 |
|---|---|
| width | **1480** (원본 1776px x 1.25 / 1.5) |
| height | **888** |
| groundY | **800** (그림 잔디 윗면 띠 784~797의 가운데 790px → 월드 800) |
| 배율 | 원본 1px = 에셋 1.25px = 월드 0.833 |
| spawn | (667, 800): 파라솔과 벤치 사이 광장 |
| platforms | **11개** |
| spawns | **7개** |
| 용량 | 0.27 MB (ground.webp q88 0.26 MB) |

좌우 패널이 오면 width는 대략 패널 수 x 1480 - 겹침 100 x (패널 수 - 1)이 된다. 지면 행 기준은 가장 낮은 패널이라 groundY가 몇 단위 바뀔 수 있다.

## 3. 레이어 / manifest

| 파일 | parallax | y | px | 월드 | 비고 |
|---|---|---|---|---|---|
| sky.png | 0 | 0 | 16x1332 | 10.667x888 | stretchX. 지면 레이어 행 평균색 (카메라가 월드 위로 넘칠 때만 보임) |
| ground.webp | 1.0 | 0 | 2220x1332 | 1480x888 | **전부 불투명**(하늘, 원경, 마을, 지면이 한 장). 손실 WebP q88 |

- clouds, far, mid는 **없다**. 그림이 한 장이라 깊이를 나눌 수 없어 패럴랙스는 생략했다. manifest `layers`에 항목 자체를 넣지 않았다. assets.js는 `layers` 배열을 그대로 읽고, 실패한 레이어만 빼므로 동작한다. `--install`은 옛 clouds/far/mid.webp 파일을 지운다.
- manifest 키: `density, width, height, groundY, spawn, layers, platforms, spawns`(기존과 같음). 참고용 `source`(패널 이름, 배율, 하늘 패딩, 겹침)를 추가했다. 프런트는 무시해도 된다.
- 카메라: 지면 근처에서 시야(720)의 아래 끝이 월드 888에 맞으면 월드 168부터 보인다. 덧붙인 하늘은 위쪽 발판에 섰을 때만 보인다.

- 측정 방법
  - 잔디 섬: 잔디색 비율이 90%를 넘는 첫 행을 윗면 윗끝으로 잡고, 그보다 3px(원본) 아래를 서는 선으로 정했다. x1~x2는 그 아래 4px 행에서 이어진 잔디 구간이다.
  - 지붕 턱, 처마, 벤치: 4배 확대 크롭에서 직접 읽었다.
  - check.py가 최종 ground.webp에서 잔디 섬과 지면의 윗면을 다시 찾아 대조한다. 서는 선은 윗면 윗끝보다 에셋 3~5.5px 아래였고, 모두 통과했다.
- 도달성 (physics.js 기준: JUMP_APEX 105.6, SUPER_APEX 225.6, 여유 6, 가로 간격 70 이내)
  - 일반 점프만으로는 c-bench 하나만 닿는다. 그림 구조상 지면에서 첫 층(카페 턱, 처마 625)까지 175가 높다.
  - 슈퍼 점프를 쓰면 11개 모두 닿는다. 필요한 최소 슈퍼 점프 수는 다음과 같다.
    - 0회: c-bench
    - 1회: 카페 턱, 처마, cherry, lamp, low, fence, flower. 턱이나 처마에 오른 뒤에는 일반 점프로 이어진다.
    - 2회: c-isle-lt, c-isle-bench, c-isle-cherry2
  - 일반 점프만으로 다니게 하려면 그림 밖에 디딤 발판을 더해야 한다. 그림과 맞지 않아서 이번에는 넣지 않았다. 메인이 결정할 사항이다(예: 사다리나 밧줄을 프런트에서 그리기).

## 7. 자기 평가 / 알려진 문제

- 캐릭터(약 120)와 건물의 비율이 자연스럽다. 상점 진열창 높이가 캐릭터 키와 비슷하다. 몬스터(주황 버섯, 초록 슬라임, 파랑 달팽이)는 배경 위에서 잘 보인다.
- 그림이 한 장이라 패럴랙스 깊이감이 없다. 원경도 카메라와 함께 움직인다.
- 1.25배 업스케일이라 확대해 보면 살짝 부드럽다. 게임(k=1, 화면 = 원본의 약 0.83배)에서는 선명하다.
- 덧붙인 하늘: 왼쪽 위 구름이 그림 위 끝에서 잘린 부분은 그라데이션으로 흐리게 이어 붙였다. 맨 위 발판에서 위를 볼 때만 보인다.
- 처마(625)와 카페 턱은 돔 앞에 서는 모양이다(한 방향 통과라 문제는 없다).
