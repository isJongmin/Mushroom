## 2. 물리 값 (월드 단위, `PHYS`)

| 항목 | 값 |
|---|---|
| 중력, 점프 | 2000/s², 초속 650 (최고 105.6) |
| 발판 | manifest `platforms[{id,x1,x2,y}]`. 0 < y < 440이고 x2 − x1 ≥ 1인 것만 쓰고, 최대 64개다. 내려오는 구간에서 "구간 최고점 ≤ 발판 y < 끝 y"이고 x가 [x1, x2] 안이면 착지한다. 구간 안에서 꼭대기를 지난 경우도 포함하며, dt 0.1에서도 착지한다. 올라갈 때는 통과한다 |
| 걸어 나감 | 서 있는 발판의 x 범위를 벗어나면 vy 0으로 떨어진다. 지면 440과 x 32~2368 경계는 그대로다 |
| 맵 위 끝 | 발 y ≥ 0 (`ceilY`). 위로 가다 닿으면 vy를 0으로 만든다 |
| ↓ + 점프 | 발판 위에서는 그 발판 id를 0.25초 무시하고 vy 0으로 떨어진다. 지면에서는 아무 동작도 하지 않는다(점프 입력만 소비) |
| 엎드리기 | 땅이나 발판에서 ↓/S를 누르는 동안이다. 좌우 이동, 점프, 슈퍼 점프가 모두 안 된다. 공중에서 누르면 착지할 때 엎드린다 |
| 대시 ←/→ | 수평 1100 × 0.22초, 그 동안 중력 절반, 위로 350. 실측 거리 242(걷기를 더하면 245~253), 높이 57 |
| 높이 뛰기 ↑ | 초속 950으로 지면에서 225.6 오른다. 키보드 ↑↑는 첫 ↑가 일반 점프라서 실측 최고 높이가 약 288이다(두 번째 누름 때의 높이 + 225) |
| 쿨다운 / 공중 | 0.8초다. 공중에서는 1회 쓸 수 있고 착지하면 다시 충전된다. 땅에서 쓰거나, 더블탭 첫 누름으로 막 뜬 경우(`airT ≤ 더블탭 경과 + 0.05초`)에는 충전을 쓰지 않는다 |
| 더블탭 | 같은 묶음(왼쪽 ←/A/터치 왼쪽, 오른쪽 →/D/터치 오른쪽, 위 ↑/W/터치 점프)을 300ms 안에 두 번 누를 때다. 다른 묶음을 누르면 끊긴다. Space는 제외한다. 쿨다운에 막힌 요청은 쌓지 않는다 |
| 상태 s | `idle, walk, jump, fall, prone`. 수신한 `crouch`는 `prone`으로 바꾼다. 프레임은 `prone`, 없으면 `crouch`(지금 manifest [10]), 그것도 없으면 idle이다 |

원격: x는 기존대로 추적하고, 대시 fx를 받은 뒤 0.35초 동안은 추적 속도를 최소 1100으로 둔다. y는 받은 (도착 시각, y) 기록을 120ms 늦게 재생하며 두 기록 사이를 직선 보간한다. 물리는 다시 계산하지 않는다. 그림자는 아래 면(발판이나 지면)에 그린다.

세로 카메라: 시야 세로가 540(맵 높이)보다 작을 때만 움직인다. 1280x800과 360x640은 사실상 고정이다. 땅이나 발판에 서 있으면 그 높이를, 떨어지면 떨어지는 높이를 기준으로 삼는다. 위로는 머리가 시야 위 8% 안으로 들어올 때만 따라간다. 목표 camY는 `clamp(기준 − 0.66·viewH, 0, 540 − viewH)`이고 0.12초로 부드럽게 따라간다. 1280x400 실측: 지면 212, 발판 170에서 0. 맵 위로는 보이지 않는다.

## 3. 이펙트 (`game/fx.js`)
- 시작 지점에 큐브 파티클 10~16개(reduce면 5개)를 뿌린다. 크기 5~10, 수명 0.32~0.48초, 중력 900이다. 색은 캐릭터 대표 색(idle 프레임 몸통 평균), 그 밝은 색, 흰색이다. 3톤 16px 스프라이트를 색마다 한 번 그려 재사용하고 캐시 상한은 24개다. 파티클 전체 상한은 160개이고 넘으면 오래된 것부터 버린다.
- 잔상은 0.035초 간격으로 4개(reduce면 1개)를 기록해 투명도 0.62부터 줄여 가며 그리고, 수명은 0.45초다. 바람 줄기는 진행 반대쪽(위로 뛰면 아래쪽)에 흰 줄 5개(reduce면 2개)를 0.34초 동안 그린다. 모두 0.5초 안에 사라지는 것을 확인했다.
- 그리는 순서: 맵 → 그림자 → 잔상·줄기 → 아바타 → 파티클 → 라벨·말풍선.
- 송신: 다음 move에 `fx: 'dash-left'|'dash-right'|'dash-up'`을 1회 싣는다. 화면의 100ms 제한을 건너뛰고, 어댑터도 급송한다(2초 안 4회 상한, 넘으면 보통 제한). 원격은 보이는 위치에서 재생한다. 정상 사용에서 `fxSent == superJumps`다.
- 계측: `getState().fx = { particles, ghosts, streaks, sprites, bursts, spritesMade, dropped, superJumps, fxSent }`, `getState().world = { platforms, camY }`, `me.{grounded,on,airCharge,cool,dashing}`.

## 4. 방 삭제 흐름
- 방장 판정: 로비 `list_rooms`의 `mine`, `createRoom` 결과(만든 방은 mine)를 `app.go('room', { owner })`와 sessionStorage `mushroom:room.owner`에 둔다. 새로고침하면 `list_rooms`의 mine을 우선하고, 목록을 받지 못하면 저장된 값을 쓴다.
- 방 HUD에서는 방장에게만 `room-delete` 버튼이 보인다. 버튼을 누르면 `modal-delete-room`이 열린다(ui/modal.js, "방을 삭제하면 모두 로비로 나가요.", 취소/삭제, Esc 취소, 처리 중에는 Esc를 무시한다). 모달이 열린 동안에는 게임 키를 받지 않는다. 확인하면 `deleteRoom`을 부르고, 성공하면(또는 `room_closed`가 먼저 오면) 한 번만 처리한다.
- `room_closed`를 받으면(방장 포함) 입력과 모달을 정리하고, sessionStorage를 지우고, 상태기계 close(removeChannel)를 최대 2초 기다린 뒤 로비로 간다. `leave_room`은 부르지 않는다. 배너는 방장 본인 화면에 "방을 삭제했어요.", 그 밖에는 "방장이 방을 삭제했어요."(info)다.
- 로비: 내 방 행에 `room-delete`(빨강) 버튼을 둔다. 같은 모달을 거쳐 성공하면 info 배너 "방을 삭제했어요."를 띄우고 목록을 갱신한다. NOT_OWNER면 모달 안에 오류를 보이고, ROOM_NOT_FOUND면 "방이 사라졌어요"를 띄우고 목록을 갱신한다.
- 채널을 놓친 경우: 하트비트가 NOT_MEMBER나 ROOM_NOT_FOUND를 받으면 `list_rooms`로 방이 있는지 확인한다. 없으면 재입장 없이 위와 같이 로비와 "방장이 방을 삭제했어요."로 간다. 재입장(재연결)이나 새로고침 재입장이 ROOM_NOT_FOUND를 받아도 같다.
  - **메인 확인 필요**: 지시는 "NOT_MEMBER면 자동 재입장 없이 로비"였지만, 방이 남아 있는 NOT_MEMBER(10분 비활성, 모바일 백그라운드)에서는 사이클 6 계약대로 조용히 재입장하게 남겼다. 이렇게 하면 "방장이 삭제했어요"를 잘못 띄우지 않고 e2e 16도 유지된다. 방이 목록에 없을 때만 삭제로 처리한다. 지시대로 NOT_MEMBER에서도 항상 로비로 보내려면 room.js `heartbeat` 래퍼 한 줄만 바꾸면 된다.

## 6. 다른 역할 요청
- 백엔드: (1) `delete_room`이 `room_closed`를 보낸 뒤 멤버 행을 지우면 다른 클라이언트의 다음 heartbeat가 NOT_MEMBER/ROOM_NOT_FOUND를 받는다. 프런트는 둘 다 처리한다. (2) `list_rooms.mine`이 없으면 프런트는 false로 본다. 그 경우 로비 삭제 버튼과 새로고침 후 방장 판정이 동작하지 않는다(만든 직후는 createRoom 결과로 동작). (3) `delete_room` 호출 빈도 제한이 있으면 오류 코드를 알려 주세요(지금은 RATE_LIMITED를 "삭제하지 못했어요"로 표시).
- 아트: (1) manifest animations에 `prone`이 들어오면 자동으로 쓴다. 지금은 `crouch`[10]로 대체 중이다. (2) 말풍선 위치는 prone 프레임의 알파 bbox 맨 위로 자동 계산하므로 별도 값은 필요 없다. (3) platforms 정본 10개를 확인했다(shelf-left 착지 확인). 가장 높은 secret-sky(85)와 secret-chest(100)은 슈퍼 점프 전용 높이다.

## 7. QA 확인 항목
1. 발판(아트 정본 platforms): 아래에서 뛰면 통과하고 위에서만 착지한다. 끝을 지나면 떨어진다. ↓+점프로 0.25초 동안 그 발판을 통과해 아래로 내려간다. 지면 ↓+점프는 y 변화가 없다. 층 간격 90은 일반 점프로 오를 수 있다.
2. 엎드리기: `me.s='prone'`, frame은 manifest prone(없으면 10)이다. 좌우, 점프, 슈퍼가 모두 안 된다. 원격에서 s prone, 말풍선이 낮아진 머리 위에 온다.
3. 슈퍼 점프: ←←/→→ 대시 거리 약 242(높이 57), ↑↑ 높이 약 288(지면 기준 225 + 첫 점프분). 쿨다운 0.8초. 공중 1회 후 `me.airCharge=false`, 착지하면 true. 300ms를 넘긴 두 번 누름은 슈퍼가 아니다.
4. 이펙트: `getState().fx.bursts`가 로컬과 원격 모두 1씩 늘고, 0.5초 뒤 particles/ghosts/streaks가 0이 된다. `fxSent == superJumps`. reduced-motion에서는 파티클이 5개 이하다.
5. 방 삭제: 방장만 HUD 버튼이 보이고, 모달 취소/Esc/확인이 동작한다. 두 탭 모두 로비로 가고 배너 문구가 각각 맞다. 로비 mine 버튼으로 삭제할 때 방 안 사람이 로비로 간다. confirm() 호출이 없다.
6. 채널 놓침: 방 행만 지우고 탭 복귀(하트비트) → 로비 + 배너. 멤버 행만 지운 경우는 조용한 재입장(e2e 16)이다.
7. 세로 카메라: 1280x400처럼 낮은 창에서 높은 발판에 오르면 camY가 줄어들고(≥ 0), 지면으로 돌아오면 원래 구도로 돌아온다.
8. 모바일 360x640: 4버튼 문구 "엎드리기", 겹침 없음, 점프·좌우 더블탭 슈퍼, 엎드리기+점프 동시 = 내려가기.
9. 실서버(외부망): `delete_room` 후 다른 기기에서 room_closed 수신, `list_rooms.mine`, fx 급송이 Supabase broadcast 한도에 걸리지 않는지(2초에 4회 상한).
