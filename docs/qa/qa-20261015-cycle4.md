## 2. 정적 점검 (항목 30, 31)

실행 명령: 저장소의 `supabase/migrations/20261015000000_rooms.sql`과 `src/client/` 텍스트를 정규식으로 검사 (`static-final.log`). 검사 줄은 기대 값을 명시했고, 허용 목록에 없는 항목을 세는 방식이다.

- 30 마이그레이션 (OK 21 / UNV 2)
  - 테이블 직접 권한 없음 (anon/authenticated grant 0), 4개 테이블 revoke all, RLS enable, restrictive deny 정책 4개
  - password_hash가 반환 타입, return query, jsonb 응답 어디에도 없음. 참조 8줄 모두 허용 목록 안
  - public 함수 7개 (create_room, heartbeat, join_room, leave_room, list_rooms, recent_messages, send_message) 모두 security definer, `set search_path = ''`, anon 회수, authenticated만 허용
  - realtime 수신/송신 정책: authenticated 한정, `can_access_room_topic`(멤버 행 확인)만 사용, `using (true)` 없음
  - 클라이언트 직접 insert/update/delete 권한 없음 (RPC만)
  - UNV: 대시보드 설정 (Allow public access 끄기, 익명 로그인 켜기), 실제 Supabase에서 RLS 우회 시도와 `realtime.send`의 RLS 통과 여부
- 31 클라이언트 (OK 8 / 실패 0)
  - innerHTML, outerHTML, insertAdjacentHTML, document.write, eval, new Function 0건
  - service_role, JWT, secret key 0건. supabase.js 코드에 service_role 없음 (anon key만)
  - supabase.js 채널 `private: true`. 클라이언트가 `chat` 이벤트를 보내지 않음
  - 프로필 저장값은 `{nickname, avatar}`만. local 모드 비밀번호는 PBKDF2 해시만 저장
  - config.js 키 비어 있음
